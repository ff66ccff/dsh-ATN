# 2026-10-04 pilot 后：内生反馈、可选验收与重连观测

本轮将免费局部遥测与可选宿主验收分开，取消有验收收益才允许重连的门槛，加入每节点预算和孤儿任务认领。它不改写[原 pilot 结果](PILOT_RESULTS_2026-10-04.md)：原十次真实模型运行中没有主动重连，仍不能归因拓扑收益。确定性回归使用真实 Harness 内核和脚本模型，不等于新增真实模型收益证据。

## 治理独立于通信

治理暂不注册为默认模型工具：`atn_propose`、`atn_vote` 和 `atn_renew` 从工具面移除。宿主仍可通过 `ctx.atn` 的相应方法管理已有流程，其持久化、授权和恢复语义保留。当前默认九个工具及九行共享规则聚焦执行、观测与局部决策。

`atn_feedback` 允许真实请求者将 `accepted/rejected/needs-more` 写入独立的 `localFeedback`，不写宿主 `acceptance`。评价绑定提交哈希，不能自评；`needs-more` 可变成最终判定。`atn_publish` 保存有界自报知识索引，发现同时返回来源明确的本地评价和宿主验证。自动重连样本的本地比较记录为 `requesterEvaluation`，只描述可比工作被认可的比例变化；宿主 `evaluation` 仍要求独立验证与完整可比成本。详见 [P0/P1 机制实验](FEEDBACK_MILESTONE.md)。

新提案的审批人是全网其他 `active` 且 `published` 节点，按 id 稳定排序；不读取 `peerIds`，不受四个通信邻居上限影响。先断边或只连接赞同者不会缩小审议范围。提案创建后的名单永久冻结，之后的出生、换边和退出都不改旧票授权；draining 节点仍可履行旧票。

`goalHistory[0]` 的 `objective`、`successCriteria`、`constraints` 构成不可通过模型提案改写的启动契约。`GoalDocument.plan` 是可选的协作计划字段，只有它可通过全票提案修改。此处保护的是启动时记录的字段；当前 `atn_start` 仍由入口模型填写，并不等于已将人类原始意图作语义形式化。计划必须服从契约，但运行时不声称能判定任意自然语言计划是否语义冲突。

旧记录无需改写。旧提案保留冻结名单；若待提交的旧提案修改启动契约，最终提交时取消，不能用旧票绕过保护。历史修订曾改变启动三字段时，即使同版本快照已被读取，恢复也会补发独立标识的初始契约；历史仍原样保留。全网审议仍受邮件额度限制，额度不足时原子拒绝，不缩小审批范围。

## 任务提交、验收与依赖

任务状态保持兼容：`open / completed / failed / unreachable` 描述执行与提交。`completed` 不代表正确，独立的 `acceptance` 才描述宿主验收。旧任务缺失该字段时按未验收处理。

宿主使用 `ctx.atn.verifyTask(networkId, taskId, validator)` 执行同步纯检查；不存在可让模型传 `passed=true` 的验收工具。验证器获得冻结的任务副本，返回判定、说明、非空证据引用和可选测量。异常或返回 `null`（不适用）不会写入验收。验收绑定任务契约、结果、依赖和身份的 SHA-256，结果变化后不能继续作为已验证事实。一次性验收不可改票；修正必须创建新尝试。

示例宿主装配（标准答案保留在宿主，不写入模型上下文）：

```ts
await ctx.atn.verifyTask(networkId, taskId, {
  id: 'numeric-contract/v1',
  validate(task) {
    return {
      passed: task.result?.summary === '42',
      summary: 'Checked the exact required result.',
      evidence: [`check:${task.id}`],
      metrics: { comparisonKey: 'numeric-work/budget-v1', cost: 150, costUnit: 'tokens' },
    }
  },
})
```

示例只是精确答案检查的接口演示。实际宿主必须提供适用于任务的独立验证器和真实测量；不能把同伴赞同、模型自评或占位数值写成验收证据。导出的 `createExactJsonValidator` 可用于离线 JSON 契约。当前插件没有通用的自然语言正确性验证器，也没有自动把 pilot 最终 oracle 变成在线答案提示。

`atn_spawn` 和 `atn_send(kind=task)` 接受：

- `dependsOn`：至多 16 个已存在、已提交且没有有效宿主拒绝的上游任务。不再要求安装验收器；开放、执行失败、有效验收失败、不存在和重复依赖仍拒绝。新任务只引用已有提交，保持 DAG，不建立等待上游的占位任务。引用未验收提交不使其成为已验证事实。
- `retryOf`：原请求者重试执行失败、不可达或验收失败的任务。旧尝试不覆盖，原依赖必须保留，可增加新的可用上游提交。
- `atn_status(taskIds?)`：合并原任务读取与同伴发现接口。最多读取 16 个本网络任务；省略时读取自己请求或持有的最近任务。可看到依赖、重试来源、提交结果、验收证据、遥测、孤儿任务与自身预算。

创建子节点前检查依赖，正式发布时再次检查。稳定邮件 id 的重试也核对依赖和重试来源，不能复用 id 换任务契约。入口节点通过 `atn_finish(scope="network")` 完成协议收尾：开放任务、待审提案和待投递邮件结清并不证明最终答案正确，也不强制所有历史尝试通过验收。原 `ctx.atn.deliver` 宿主方法保留。

当持有者失败或退休且原失败/不可达任务没有后续尝试，任务进入孤儿可见集。没有开放任务的节点可以 `atn_status(claimTaskId=...)` 原子认领；原请求者、任务内容和依赖保留，新 holder 自主接手并通过 `retryOf` 关联原尝试。并发调用不会创建两个恢复任务。它给出一条自发分工规则，不自动指定领域角色或替模型决定哪项工作最相关。

## 不依赖验收的局部遥测

`atn_status` 同伴摘要的 `telemetry` 来自运行时记录，按调用者自己委派给该同伴的工作提供：

- 累计 assigned、open、completed、failed、unreachable 数量，以及重试和恢复次数。
- 最近至多八项任务的耗时、结算延迟、持有者步骤观察窗口；成本缺失时为 `null`。
- 同伴的已用步骤及剩余逐节点预算；这是同伴总步骤，不是调用者任务的独占成本。
- 可见直接依赖任务的失败数量；这是依赖关联，不证明上游结果导致下游失败。

`completed` 始终只是提交，遥测不构造通过率或伪造验收。任务步骤采用创建与结算时的 holder 计数差；开放任务使用当前计数，重叠任务共享窗口。重试指新任务引用 `retryOf`；恢复指接续不可达尝试，或更换已失败/退休的原持有者。墙钟时间不等于模型用时或费用。

已有拓扑快照同时附带紧凑的局部遥测。它只附加到正常模型输入，不生成额外模型调用、邮件或独立唤醒。Session 日志保存图快照与遥测指纹，拒绝/取消的未记录输入不消耗通知。仅经过时间和观察者自己的步骤变化不触发重复提示；下一次真实同伴进展才更新。

`stepBudget` 现在对每个节点独立执行，包括入口节点；耗尽后节点退休，其未完任务保留为可恢复尝试。网络 `stepsUsed` 仅作总量报告。它测量获准步骤，不覆盖提供商内部重试或额外辅助调用，也不代替实验的真实 token 计费。旧记录缺失逐节点计数时，首次升级后获准步骤从新的零基线开始累计，无法准确追溯分摊旧全网历史；缺少计数边界的旧任务成本仍为未知。旧网络的总计数继续累加，因而可能混合升级前后两种计数范围，不保证等于现存逐节点计数之和。

`verifiedFeedback` 作为可选增强保留，按调用者自己委派给该同伴的任务汇总最近至多八条结果。宿主验收通过、验收失败、自报失败和未验收分开表示，保留任务 id、验证器、比较组、成本单位和信息标签。没有安装验证器时，不影响遥测、任务依赖或有效换边。

## 重连决策与自动观测

模型工具 `atn_rewire` 只需完整的新邻居列表。原宿主 API 的 `intent` 与显式证据输入保留兼容，但不再授予或拒绝重连权限：

`atn_rewire` 的 `intent` 有两种：

| 意图 | 行为 |
|---|---|
| `exploration`（默认） | 记录自主选择及其运行时观测，不要求收益样本 |
| `verified-improvement`（宿主兼容字段） | 若提供比较样本则记录可选验收评估；证据不足或退化不会阻止有效换边，也不会把模型的意图当作已验证收益 |

可选验收评估仍采用保守规则：样本等量、每组至多八条、覆盖被移除/新增同伴的本地工作，且验证器、比较组和成本单位一致；质量通过率不下降，平均提交延迟和平均成本都不增加，至少一项严格改善，才标记 `observed-improvement`。未知值、无关任务、重复任务和不匹配摘要不能支持该标签；有得有失为 `mixed`，证据不足如实记录。此处只是判定声明是否有支持，不再是执行门。宿主通过 `comparisonKey` 声明任务与预算可比，运行时无法仅从自然语言证明可比性。

每次获准重连调用都保存 `rewireHistory`：原/新边、意图、可选验收评估及 `observations`。保持原边集的决定也记录；没有原来的 64 次硬上限，早期记录不被覆盖。无效边列表、非活动节点及关闭/过期网络仍受基本协议检查。出生连接与失活补位是独立机制，不能计为模型主动换边。

`observations.before` 冻结旧邻居的局部工作与步骤快照，`after` 保存新邻居当前快照。运行时在原子任务/步骤 mutation 中自动刷新每个节点最近一次重连的 `after`；再次重连后旧记录冻结。计数是该调用者累计委派给各同伴的任务，延迟与任务步骤均值取最近有界样本，不自动匹配任务难度，也不保证 `after` 样本全在重连后产生。两侧保留观测时间和任务 id，便于实验离线筛选。旧记录缺少 `observations` 时保留原样，不倒填虚构历史。

运行时观测与验收评估均保存 `causalClaim: false`：历史样本改善不证明重连造成收益，也不保证未来收益。信息标签仅展示，不作为未经验证的额外得分。domain 版本保持 1，新增字段可选，旧记录继续读取。

## 验证与下一道实验门

确定性测试覆盖无验证器时的遥测与任务依赖、缺失成本保持未知、无额外请求的反馈、日志游标恢复、逐节点预算、并发认领与重连自动观测。已有治理隔离、初始契约保护、失败重试溯源、验收摘要绑定和完整内核恢复继续保留。验收退化现在作为观测保存，不再拒绝换边。

上一轮验收/治理实现的历史检查曾通过 `npm run typecheck`、`npm test`、`npm run build`，含 266 项运行时/单元/集成测试及八项前端测试；这不是本轮变更后的测试数量。旧真实模型 pilot 报告和 Web profile smoke 结果保持原样，不能替代对本轮机制的重新验证。

八节点四出边的可达性约束较弱，不能仅凭节点数宣称拓扑有意义。新变化依赖链实验使用八节点、两出边和未知证据位置，并在中途改变路径及持有者；白板跨拓扑可达，另设无白板对照。在线宿主检查器可增强质量观测，但不是运行前提；最终独立 oracle 仍须检验答案。应记录节点实际创建数、有效边变化、失败恢复、每节点及全网成本，比较禁重连、主动重连与其他相同资源对照，并区分重连调用和真实边变化。确定性任务族与上述机制尚不构成真实模型的成本收益、任务族泛化或统计显著性结论。
