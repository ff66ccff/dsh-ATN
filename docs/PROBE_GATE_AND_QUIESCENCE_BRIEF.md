# dsh-ATN 探针门分位修正与静默成因定位实施说明

这份文档交给实现代理执行。上一轮把 120 秒改为 600 秒后，失败**性质变了**：五个 seed 无一撞期限（最长 551.7 秒），全部以 `quiescence` 结束，224 次调用，provider 利用率 **99.9%**。所以本轮**不再调预算**，只做两件零模型调用的事：

1. **修正规划门的延迟输入**——现行门用的是幸存调用均值，而本批实测延迟全部高于该均值，**五个里有四个会让门拒绝这个配置**；
2. **定位静默成因**——网络在还有 6–8 个未完成任务、邮件队列为空的情况下停止推进，而入口节点在全部五个 seed 里都是步数耗尽者。

**本轮不派发任何真实模型调用。** 全部产出为纯计算与既有 artifacts 分析。在 4.1–4.3 完成前，**不得**以「再放宽预算」的方式重跑探针。

实现代理在动手前必须先完整阅读本文件，并按第 9 节完成标准交付。

## 2. 本轮要解决的核心问题

### 2.1 门的延迟输入被本批自己证伪，而报告没有把实测值代回门

上一批已诚实指出「历史均值偏乐观」。但**没有做后续那一步**：把本批实测延迟代回门，看准入结论是否翻转。代入后：

| 延迟输入 | `requiredDeadlineMs = 68L + 30000` | 600,000 ms 是否放行 |
|---|---:|---|
| 8144（门实际使用） | 583,792 | **放行**（余 16.2 s） |
| 8660（seed 17 实测） | 618,880 | **拒绝** |
| 9504（seed 45 实测） | 676,272 | **拒绝** |
| 10282（seed 31 实测） | 729,176 | **拒绝** |
| 11133（seed 59 实测） | 787,044 | **拒绝** |

**四个实测值里有四个会让门拒绝该配置。** 只有那个乐观均值让它通过。所以门在边界上是**系统性偏松**的——不是随机误差，而是方向一致的选择偏差（幸存偏差 + 排除取消样本）。

### 2.2 静默判据只看活性，不看义务，因此不能回答「为什么停」

现行判据是「没有 agent 在跑」，所以一个**发出任务后集体空闲、任务还开着**的网络会被如实报成 `quiescence`——这是正确的**活性**观测，但对**成因**零信息。

而 artifacts 显示了一个很具体的签名：**任务开着（6–8 个）、邮件队列为空、入口节点步数耗尽**。这三件事同时出现，指向的不是资源饥饿，而是**协议推进停滞**。本轮要把这个签名从「观察到」变成「定位到」。

### 2.3 入口的步数去向无法从现有产物回答

入口在五个 seed 里都是步数消耗最高者（12/11/12/9/12），其余节点只用 2–8。但事件日志把工具名匿名化为 `tool-1`…`tool-4`，所以「入口的 12 步花在哪」**目前不可直接读出**。

一个强假设但**尚未确立**：seed 17 中入口调用了 `tool-2` **7 次**（其余节点各 1 次），而网络级 `priorStatusQueryCalls: 13`——若 `tool-2` 是发现类工具（`atn_status`），则**发现抖动主导了入口预算**。**该映射必须被确立，不得假定。**

## 3. 目标

- **G1 无删失样本**：延迟输入改用本批 224 次调用（`aborted = 0`）的样本，并记录删失状态与来源。
- **G2 分位原则**：延迟输入不再用均值，改用一个**由独立于被判定批次的原则所选定**的分位（或等价的上偏统计量），并**公布敏感性曲线**。
- **G3 结论翻转可核验**：以实测延迟重算，给出「600,000 ms 配置在四个实测延迟下均被拒绝」的算术，并说明原准入为何偏松。
- **G4 门自证不偏松**：门必须同时给出**它会拒绝什么**与**它会放行什么**，且放行的含义被显式表述为「覆盖到哪个分位」。
- **G5 静默可归因**：把「活性静默」与「义务未完成」分开记录；对每个未完成任务给出持有者与状态；给出入口步数的逐类去向。
- **G6 工具身份可读**：确立并留档工具索引到 ATN 工具的映射，使「入口的步数去向」可复核。
- **G7 零模型调用**：本轮全部产出为纯计算与既有 artifacts 分析；不派发任何真实模型调用。
- **G8 零行为变更**：`src/` 运行时行为逐位不变；不重写已归档实验的 `sourceHashes`。

## 4. 必须实施的项目

### 4.1 改用无删失延迟样本（G1）

要求：

- 延迟输入改为从本批 224 次调用的 `provider-calls.jsonl` 逐 call 配对 dispatch→finish 得到，并**断言 `aborted = 0`**（即样本无右删失）作为使用前提。
- 必须记录并输出：样本来源文件与其 SHA-256、样本数、**删失状态**（本批应为「无删失」）、以及**与上一批样本的差异说明**（上一批为 76 中 71 存活，有幸存偏差）。
- **不得**把本批样本与上一批样本混合成一个池；若需要合并，必须说明理由并分别列出两批的分位。

验收测试：

- 断言样本数等于该批 `metrics.totals.attempts` 之和（224），且 `aborted` 之和为 0。
- 断言输出含来源哈希与删失状态字段。
- 断言两批样本未被静默合并（可通过分别输出的分位值核对）。

### 4.2 分位原则与敏感性曲线（G2、G4）

要求：

- 延迟输入改用一个上偏统计量（高分位或等价量）。**分位的选择必须由一个与被判定批次无关的原则给出**，并在文档中写明该原则。
- **不得**以「哪个分位会让 600 秒被拒绝」为理由选择分位。这与「挑一个刚好能通过的期限」是同一类错误，方向相反但性质相同。
- 必须输出**敏感性曲线**：至少覆盖 p50 / p75 / p90 / p95 四档，每档给出该档延迟值、`requiredDeadlineMs`、以及对 600,000 ms 与 120,000 ms 两个既有条件的准入结论。**公布整条曲线，而不是单点结论。**
- 门的准入结论必须**显式表述其覆盖含义**，例如「本准入覆盖观测服务时间的 p90」。不得只输出「通过／不通过」而不说覆盖到什么程度。

验收测试：

- 断言敏感性曲线四档齐全，且各档的 `requiredDeadlineMs` 与所用分位值一致（算术可复核）。
- 断言门的输出含覆盖含义字段。
- 断言分位原则被写明，且该原则的表述**不引用任何具体批次的结论**（可由文本断言或人工核对）。

### 4.3 重算准入并如实报告翻转（G3）

要求：

- 用 4.1 的样本与 4.2 的分位，重算 600,000 ms 与 120,000 ms 两个条件的准入。
- 明确给出「**原准入为何偏松**」的结论：不是随机误差，而是**方向一致的选择偏差**（幸存调用均值 + 排除取消样本），并用第 2.1 节的表作为证据。
- **必须明确写出**：若门在上批运行前使用本批可得的上偏延迟统计量，**该配置会被拒绝**。这是本轮最重要的单一结论。
- 重算必须**零模型调用**，并可在 CI 重跑。

验收测试：

- 断言 600,000 ms 在上偏分位下**被拒绝**，且拒绝原因指向期限而非其它维度。
- 断言步数与调用上限两个维度在重算中**仍判定充足**（12 ≥ 9、96 ≥ 68），即门不是对所有维度一起拒绝。
- 断言重算脚本不读账号、不联网、不装载 provider。

### 4.4 分开记录活性静默与义务未完成（G5）

要求：

- 停止记录必须**同时**包含：停止的**活性原因**（无 agent running 持续 ≥200 ms）与**停止时的义务状态**（未完成任务数、邮件队列、阶段 checkpoint 状态）。
- 停止标记不得只用 `phase-1-quiescence` / `phase-2-quiescence` 这类**只反映活性**的字符串而不带义务信息；若保留该字符串，必须与义务字段成对出现，且文档写明该字符串**不表示协议已完成**。
- 必须区分并分别计数：`quiescence-with-obligations-open` 与 `quiescence-with-obligations-complete`。本批五个 seed 应全部归入前者。

验收测试：

- 断言停止记录含义务字段，且本批五个 seed 被归入 `quiescence-with-obligations-open`。
- 构造一个义务已完成的确定性用例，断言它被归入 `quiescence-with-obligations-complete`（**负向对照**：防止分类器把所有静默都归为一类）。

### 4.5 未完成任务的持有者与状态（G5）

要求：

- 对每个未完成任务，给出：`holder`、`requester`、`status`、`holderStepsAtCreation`、以及**持有者在停止时的状态**（是否仍 active、其步数消耗、是否已退休/失败）。
- 目标是回答一个可判定问题：**这些任务的持有者是「还活着但不再推进」还是「已不可达」？** 两者的成因与修法完全不同。
- 若现有 `task.state` 事件不足以给出持有者停止时的状态，必须补足采集，并在报告中说明补了什么。

验收测试：

- 对本批五个 seed 输出未完成任务的持有者状态表。
- 断言表中每个未完成任务都能被判定为「持有者存活」或「持有者不可达」之一，不得留空或归入「未知」而无解释。

### 4.6 入口步数的逐类去向（G5、G6）

要求：

- **先确立工具索引映射**：把事件日志中的 `tool-1`…`tool-4` 映射到具体 ATN 工具，并留档映射依据。可用的依据包括与结构化事件的互证（例如 `topology.rewire` 事件必来自 `atn_status(rewire=…)`；`task.state` 创建必来自 `atn_send(kind="task")`），以及工具 schema 或调用顺序。**不得仅凭猜测指定映射。**
- 用该映射给出**入口节点每步的工具类别分布**，并与其它节点对比。
- 明确回答：**入口的 12 步中，发现类（只读查询）占多少、协议类（spawn/send/finish）占多少、换边占多少、其余占多少。**
- 检验（但不预设）第 2.3 节的假设：若 `tool-2` 为发现类，则入口的发现抖动是否显著高于其它节点。

验收测试：

- 断言映射被留档，且每一条映射都有互证依据（不得有无依据的条目）。
- 断言输出含入口逐类分布，且各类计数之和等于入口步数。
- 断言对第 2.3 节假设给出**成立／不成立**的明确结论；若不成立，如实写出。

### 4.7 失败类别进入 headline（G8）

要求：

- 报告与汇总表必须在显眼处区分两类失败：`incorrect-proof`（提交了错误答案）与 `submission-discipline`（未提交），并给出各自计数（本批为 3 / 2）。
- 「0/5」不得作为唯一表述；必须同时说明其中 3 个 seed **确实提交了答案但答案是错的**。
- 原因：前者是**求解**失败，后者是**协议**失败，两者的下一步不同，合并会误导。

验收测试：

- 断言报告含两类计数与各自定义。
- 断言 headline 未只用 `0/5`。

### 4.8 已观测 token 阈值：可用化或去列（G8）

要求：

- 现状：准入按上报的 `totalTokens` 判定，而该字段在本批 224 次调用中**始终未知**，故 400,000 阈值**从未也不可能触发**——四个预算维度中有一个提供零保护。
- 必须择一并说明理由：
  - **(a) 可用化**：改为按已知字段之和（input + output + cacheRead）判定，并在文档中**明确写出该和不含推理 token**，因此是**偏松的下界**而非精确消耗；
  - **(b) 去列**：不再把它列为预算维度，并说明它为何不可用。
- 无论哪种，**不得**继续把一个永不触发的字段描述成有效预算约束。
- 注意：seed 45 与 73 的**已知输入单独已超过 400,000**，所以若阈值可用，这两次运行会被截断——这一事实必须写入报告，用于说明阈值不可用带来的实际后果。

验收测试：

- 断言所选方案落地，且文档中的阈值描述与实际判定字段一致。
- 若选 (a)：构造一个已知字段之和超过阈值的用例，断言它**被拒绝**（负向对照证明阈值真的会触发）。
- 断言 seed 45/73 的已知输入超阈事实被记录。

## 7. 停止条件（遇到即停下报告，不得自行绕过）

1. 工具索引映射无法由任何互证依据确立（即 `tool-N` 与具体 ATN 工具之间无可核对的联系）——报告并说明缺什么，**不得**用猜测补齐。
2. 未完成任务的持有者状态无法从既有事件判定，且补采集会改变 `src/` 运行时行为或归档哈希。
3. 本批延迟样本被发现仍有删失（例如 `aborted` 实际不为 0），使「无删失」前提不成立。
4. 4.4 的负向对照（义务已完成的静默应被归入另一类）无法构造。
5. 分位原则无法表述为不引用具体批次结论的形式。

**报告格式**：停在哪一条、实测证据（命令与输出）、已尝试的方案、建议的下一步。**不得补造证据。**

## 11. 一句话提醒

本轮最容易犯的错，是**把分位选成「刚好让结论翻转的那个值」**——那与挑一个刚好能通过的期限是同一类错误，只是方向相反。第 4.2 节要求公布**整条敏感性曲线**并写明一个**不引用具体批次结论**的分位原则，就是为了防这一点。曲线本身才是产出；单点结论不是。
