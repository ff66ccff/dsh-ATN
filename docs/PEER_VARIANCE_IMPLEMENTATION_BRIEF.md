# dsh-ATN 同伴质量差异与自适应验证实施说明

这份文档交给实现代理执行。上一轮（可测性恢复）已经完成：基础任务可解、协议面收敛、判据不再按构造不可达。本轮解决的是它暴露出的**下一个阻断点**：反馈回路已经接通，但回路里没有信号方差，因此"自适应"仍无可优化的对象。

实现代理在动手前必须先完整阅读本文件，并按第 7 节完成标准交付。

## 1. 当前基线（已独立核实）

- 工作区：`D:\dsh-ATN`。
- `npm test` 为 394 项 runtime／集成 + 8 项 UI，全部通过，0 跳过；typecheck、build、pack、smoke 通过。
- 模型工具面 6 个：`atn_start`、`atn_spawn`、`atn_send`、`atn_status`（含 `claimTaskId` / `review` / `rewire` 三个互斥可选写）、`atn_board`、`atn_finish`。
- 共同规则 6 行；固定协议字节 7,160（规则 969 + schema 6,191）。
- 真实 `fixed` 臂在链长 2、每节点 32 步、256 调用、输出 4096、观测阈值 4,000,000、期限 600 秒条件下 **5/5 两阶段正确**（Space Bunny，种子 17/31/45/59/73），无自动推进，cleanup 全部 released。
- 确定性脚本扫描 9 配置 × 5 种子 = 45/45，全部标注 `execution: scripted-test`、`liveProvider: false`、`mayInterpretTopology: false`。
- 边级评价已持久化并按 `(requesterId, holderId, comparisonKey)` 事后累计；`requesterMinSamples` 默认 2；`no-ratings-at-all` 与 `new-edge-unobserved` 已分离。

## 2. 本轮要解决的核心问题

### 2.1 回路没有信号方差

v4 五次真实运行共 19 次请求者评价：`4/0`、`3/0`、`7/0`、`3/0`、`2/0`（accepted/rejected）。**零次 rejected。** 此前两轮同样是接近零的拒绝率。

根因不是模型不会评价，而是任务里没有可评的差异：8 个节点同能力、同诚实度，每个持有约 2 条事实，被问到时都会如实回答。对同一个查询，同伴 A 和同伴 B 的答案质量相同。因此"按评分挑同伴"没有可优化的对象，全 accepted 是**正确的**观察。

**结论：在制造出同伴质量差异之前，四臂比较测的是"随机换边 vs 不换边"，不是自适应拓扑。** 这是本轮的第一要务。

### 2.2 `status.rewire` 的可发现性未经证实

`fixed` 臂按设计在工具调用前禁用换边，因此真实运行里只有 4 次被 `ablation-guard` 拦截的尝试（分布于 5 个种子），没有任何一次成功换边。如果模型找不到合并进 `atn_status` 的换边入口，自适应臂会静默失效，而实验结果会被误读为"拓扑不重要"。

### 2.3 步数余量偏薄

v4 的五个种子里，种子 45 和 59 的最大节点步数已达 30/32。自适应臂会比 fixed 臂多出换边调用，这两个种子很可能顶到天花板。

### 2.4 模型面仍带着从未触发的宿主证据参数

`atn_status.rewire` 仍暴露 `baselineTaskIds` / `candidateTaskIds`。该路径在全部真实运行中从未产生过非 `insufficient-evidence` 的判定，却占用每次调用的 schema 字节。

## 3. 目标

- **G1 制造差异**：任务中出现与同伴身份相关的、请求者可本地判定的质量差异；真实运行的评价里出现非零 rejected。
- **G2 证明可发现**：自适应臂在真实运行中确实执行换边（不是被拦、不是零尝试）。
- **G3 恢复余量**：自适应臂的最大节点步数不超过预算的 80%。
- **G4 瘦身**：模型面不再包含从未触发的宿主证据参数。
- **G5 仍然可解**：`fixed` 臂在选定配置下继续 ≥4/5 两阶段正确。

## 4. 必须实施的项目

### 4.1 在任务中引入同伴可靠性差异

要求（性质约束，不规定实现细节）：

- 对同一查询，不同同伴返回的结果必须存在**请求者可以本地判定**的正确／错误差异。
- 该差异必须与**同伴身份相关**（稳定地属于某些同伴），不能是每次随机的噪声。随机噪声无法被"换同伴"优化，也不构成选择压力。
- **不得改变任何节点的能力。** 同能力原则不变：差异只能来自节点手上的**证据状态**，不能来自模型、工具集或权限的差别。
- 差异必须可被请求者发现，否则只会产生无法评价的失败。

建议实现（可采用，也可用等效方案，但必须满足上面四条）：

- 让一部分节点同时持有某个事实的**过期副本**（旧阶段或旧版本）。它们被要求提供事实时会如实返回自己手上的版本；请求者只要检查阶段／版本标记就能判定该结果不可用并 `rejected`。
- 过期副本的分布与持有者绑定（固定在某些 slot），因此"换到一个提供当前副本的同伴"是可重复、可测的改进。
- 第二阶段继续改变有用路径与持有者，使"谁是好同伴"随阶段变化——这正是自适应拓扑该被检验的场景。

验收测试（确定性、零付费模型）：

- 同一查询打到持有过期副本的同伴，请求者能本地判定并 `rejected`；打到持有当前副本的同伴能 `accepted`。
- 过期副本的归属在多次运行间稳定，不随 seed 内随机漂移。
- 任何节点的工具集、模型路由、权限与其同伴完全一致（断言相等）。

### 4.2 让评价产生方差

要求：

- 共同规则或实验提示词必须给出**明确的拒绝判据**，而不是只说"评价结果"。至少覆盖：阶段／版本不匹配、缺少被请求的字段、返回的不是被询问的键。
- 提示词必须说明请求者**能检查什么**（阶段标记、键是否匹配、必需字段是否存在），使拒绝成为可执行的判断而不是猜测。
- 不得为了制造拒绝而引入无法判定的条件。

验收测试：

- 规则文本包含可枚举的拒绝判据；单元测试断言这些判据存在。
- 真实运行中（4.1 完成后）至少出现一次 `rejected`；若仍为 0，报告必须把它当作 4.1 未达成的证据，而不是当作正常结果。

### 4.3 确认换边可被发现

要求：

- 在四臂比较**之前**，先跑一次 `adaptive` 单臂真实探针（同样配置、≥5 次）。
- 记录并报告：`status.rewire` 的调用次数、成功换边次数、被拦截次数、以及模型是否在换边前做过 `atn_status` 查询。
- 若 5 次中少于 4 次出现成功换边，先修可发现性（例如改工具描述、改规则措辞、或在 `atn_status` 返回体里显式提示可换边），再谈拓扑比较。
- 探针结果与后续四臂结果分开统计，不用探针数据充当比较结果。

验收测试：

- 探针产出可核对的换边计数；计数为 0 时闸门明确判为"未通过"，不得继续解释拓扑。

### 4.4 重新校准步数余量

要求：

- 在 4.1 的新任务上重跑确定性扫描，并单独确认 `adaptive` 臂的步数使用。
- 选定配置需满足：`adaptive` 臂各 seed 的最大节点步数 ≤ 预算的 80%，且 `fixed` 臂 ≥4/5 两阶段正确。
- 若 32 步不满足，按 48 步档重校准；预算变更必须作为实验条件显式记录，四臂一致。
- 不得为提高通过率而修改生产默认值。

验收测试：

- 扫描输出包含每臂、每 seed 的最大步数占比；超限即判该配置不合格。

### 4.5 移除从未触发的宿主证据参数

要求：

- 从模型面移除 `atn_status.rewire` 的 `baselineTaskIds` / `candidateTaskIds`。宿主证据路径可以作为 runtime API 保留，但不再出现在工具 schema 里。
- 更新后重新测量 `toolSchemaBytes` 与 `fixedContextBytes`，给出前后数字。
- 保留 `review` 与 `rewire` 的"每次最多一个原子写"约束。

验收测试：

- 工具 schema 中不再出现这两个参数；相关宿主路径的既有测试改为直接调用 runtime API。
- 固定上下文字节数下降并记录。

## 5. 四臂比较的准入闸门（更新）

只有以下全部成立，报告才允许描述拓扑差异：

1. `fixed` 臂在同模型、同配置、同源码下 ≥5 次且 ≥80% 两阶段正确。
2. `adaptive` 臂的换边探针通过（4.3）。
3. 真实运行中出现非零 `rejected`（4.2），即评价信号有方差。
4. 各比较臂均 ≥5 次，且步数余量满足 4.4。

任一条件不成立，报告只能陈述可行性与机制状态，不得作拓扑收益或因果结论。

## 6. 必须保留的既有语义

- 入口 Agent 由宿主拥有；完成、停止、退休都不 `dispose` 入口。
- 网络记录是唯一原子持久化单元；"检查 + 修改"在同一 mutation 临界区内完成。
- 边是单向的；出生谱系只作追溯。
- 工具身份、发送者、投票者取自真实 live Agent。
- 同伴文本不构成人类授权；请求者评价不构成宿主验收。
- 白板作者权限、精确版本、分页失效与读写计量语义不变。
- `stepBudget` 不得被宣称成 token、HTTP 请求或费用上限。
- **同能力原则**：本轮引入的是证据状态差异，不是能力差异。
