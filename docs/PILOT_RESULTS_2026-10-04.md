# 2026-10-04：可靠性修复与真实模型 pilot

本轮完成了可重复调用、全网计量和外部验收的第一版实验链路。正式 pilot 共 10 次运行，8 次答案通过；这个结果不能证明 ATN 已超过 Harness Agent Teams，也不能证明群体智能涌现。两次自适应 ATN 运行都没有调用 `atn_rewire`，因此没有实际检验主动重连的收益。

## 装配与边界

模型通过真实 `dsh-opencode-go@0.1.20` 调用，宿主为 Harness `0.2.0-rc.2` 内核装配。按用户选择，本轮跳过 Muse；使用实时目录确认的 `deepseek-v4.1-flash` 和免费模型 `space-bunny-free`。这是内核实验，不是桌面 UI / CLI profile 验证。

每个模型、每种架构只跑一遍 `ledger-reconciliation`：处理退款、重复事件、账户更正与时间边界。所有 Agent 获得相同公开题目文档，宿主侧 oracle 在运行结束后验收答案，不向模型反馈正确答案。最多 3 个 Agent、全网最多 16 次可见模型调用、每次输出最多 3,072 token、180 秒期限；80,000 token 是观测准入阈值，不能保证实际用量不超出。独立候选与最终合成的消耗全部计入。

这是**相同资源上限**比较，实际消耗并不相同，不能据此声称已完成严格的成本匹配实验。各架构自行决定分工，独立池固定为两名候选加一名合成入口。

| DeepSeek V4.1 Flash | 单 Agent | 通过 | 1 | 1 | 1,627 | 5.6 |
| DeepSeek V4.1 Flash | 独立候选合成 | 通过 | 4 | 3 | 6,497 | 12.1 |
| DeepSeek V4.1 Flash | 原生 Team | 通过 | 13 | 2 | 53,564 | 33.5 |
| DeepSeek V4.1 Flash | ATN 禁主动重连 | 通过 | 9 | 2 | 57,757 | 38.6 |
| DeepSeek V4.1 Flash | ATN 自适应 | 通过 | 11 | 2 | 58,265 | 26.5 |
| Space Bunny Free | 单 Agent | 通过 | 2 | 1 | 3,215 | 6.7 |
| Space Bunny Free | 独立候选合成 | 通过 | 5 | 3 | 8,142 | 44.4 |
| Space Bunny Free | 原生 Team | 通过 | 14 | 3 | 50,403 | 40.2 |
| Space Bunny Free | ATN 禁主动重连 | 未提交 | 2 | 1 | 7,644 | 8.1 |
| Space Bunny Free | ATN 自适应 | 超时，未提交 | 10 | 2 | ≥42,173* | 180.1 |

Agent 数按持久 Session 去重。时间包括停止后的清理。带星号的一行有一次调用缺失总 token；已知数不是完整总量。所有运行清理均完成，计量没有写入失败或观察异常；“计量正常”不代表 provider usage 字段齐全。

DeepSeek 的两种 ATN 都完成了网络交付，未结任务、待发邮件和待审提案均为零。两个原生 Team 运行的待发邮件与未结任务均为零；其中免费模型选择只通过成员消息合作，没有创建任务板条目。答案提交时仍可能存在活动 Agent，随后由共同清理流程取消，因此不能把正确答案等同于所有 Agent 自然停止。

免费模型的 ATN 禁重连运行首先给 `atn_start` 提供了无效参数：缺少 `successCriteria`，且 `objective` 类型错误；接着 provider 返回 `EMPTY_RESPONSE`。自适应运行出现 provider `TIMEOUT`，停止时仍有一封 queued 邮件和一个未结任务。后者还暴露了运行时唤醒缺陷：投递在运行中的节点上进入 pending inbox，而当前请求失败后，进程内去重会阻止空闲节点重新被唤醒。该样本保留为失败记录，修复验证另列，不能事后改成通过。

该恢复缺陷已在 pilot 后修复：运行中保留 claimed 输入的去重保护；空闲时依据实际 inbox / 接收历史判断，使用公开 Inbox 与 Agent API 重唤醒，保留消息身份和队列顺序，丢失的 claim 从持久发件箱重放。已有历史收据不重复投递，停止或预算耗尽时不唤醒；旧 claim 标记不会延续到新 driver。新增八条确定性回归覆盖 TIMEOUT、同进程 claim 取消、停止、预算耗尽、初始任务与共享目标一起恢复，以及两种 inbox 边界的顺序和跨 driver 去重；故障样例在修复前能稳定复现，修复后相邻运行时测试 54/54 通过。这验证了具体恢复路径，没有通过重新抽样模型来替换原失败结果。

价格字段仅是实时目录参考费率估计，不是 OpenCode Go 订阅扣款或额度消耗。免费模型的目录费率为零；部分 DeepSeek 调用缺少计价所需字段，汇总保留未知，不能把 `null` 当成零，也不能给出完整实际账单。

## 这轮说明了什么

短题中，单 Agent 已足以求解，协作增加了明显的上下文与协议开销。本轮没有观察到重连行为，没有任务阶段变化或跨分支信息依赖，也没有多次随机重复；因此 ATN 与禁重连模式之间的数字差异不能归因于自适应拓扑。

免费模型可以完成原生协作，但本次 ATN 失败同时涉及工具参数、provider 稳定性和运行时恢复，不能用这两个样本给模型或架构下普遍结论。保留这些分类比只汇报“完成率”更有用。

此前连通性测试及旧装配记录没有合并进上表：Muse 的账户隐私拒绝、LongCat 的受限输出诊断、旧最终文本提取规则，以及 ATN 子节点输出上限未在准入前落入配置的问题，均单列在本机诊断目录。正式表只使用 `pilot-v2-20261004` 的十个连续运行，没有挑选重试中的最佳答案。

## 下一阶段

1. **先完善错误恢复和低成本协议交互。** 让工具参数错误、provider 超时和 pending 邮件有明确状态与恢复路径；用固定回归防止“节点已空闲但消息永远 queued”。减少无收益的状态查询和重复文档读取。
2. **治理与通信图分离。** 节点选择协作者不能同时决定谁有权修改全局目标；避免先删边再缩小审议范围。
3. **引入任务依赖与可验证结果。** 区分提交、通过验收和可用于下游的事实；以有证据的质量、增量信息、延迟和成本作为重连反馈，不能用同伴赞同代替正确性。
4. **设计能检验拓扑假设的保留任务。** 包括跨分支依赖、信息分散、阶段变化和节点失效；对照原生 Team、独立合成、禁主动重连与随机重连，比较质量—成本曲线，并跨任务重复。只有处理机制确实发生、消融有效且收益可复现，才讨论涌现能力。

实验门仍有明确边界：触发调用或观测 token 上限会立即取消全网，包括已准入但未完成的请求；触限失败带有这种调度策略影响。独立候选配额只为合成保留调用额度，不保证剩余时间或 token。后续统计实验应在运行前固定这些规则，评估是否改成只拒绝新调用、等待已准入调用结束。
