## 1. 固定范围

### 1.1 已确认的产品行为

- 所有节点拥有相同基础能力和 ATN 操作；当前任务与局部上下文可以不同。没有固定 planner/reviewer/executor 等能力等级。
- 子节点只表示出生来源。创建者停止或退休，不默认终止独立后代。
- 节点只持有局部信息，按需发现其他通信伙伴；发现结果不能变成持续广播的全网任务列表。
- 所有节点知道同一份简短总体目标、成功标准及共同约束。该文档持久化，属于网络，不属于一个必须永远存活的 Lead。
- 节点可以自主提出文档修改，但必须得到该提案的全体邻居明确同意。多数票、沉默、超时都不算通过，不要求用户逐次审批。
- 每个节点最多有两个上游邻居、两个下游邻居。初始对应父、祖父、选中子节点、沿所选分支的孙节点。
- 允许多个子分支。第一个成功创建的子节点成为 `selected_child`，后来创建的不自动替换。邻域不保证对称。
- 退出节点被当前拓扑跳过，自动连接原路径更外层节点；不重写出生关系。
- 新提案交给新邻居，旧提案继续由原节点处理。
- 局部任务完成后默认等待新任务；寿命可因任务需要续期。正常退休先停止接收新工作，再结清旧任务和旧审议。
- 每次聚焦一个局部任务，消息异步进入安全步界，任务请求与结果有明确关联。
- 人机交付入口保留，汇总由同能力普通节点承担，不因此垄断派发权。完成、失败、停滞、预算耗尽分别报告。

### 1.2 MVP 默认，不是用户额外指定的规则

- 单 Harness 进程、单执行环境；不实现多机或多进程共享网络。
- 向上沿出生祖先路径，向下沿已选分支寻找最近两个可接收新工作的节点。路径尽头留空，不随机或跨兄弟分支补位。零邻居不能自行批准修改。
- 空闲的 `active` 节点仍计入邻居；只跳过准备退休、已退休或已明确失败的节点，不能把暂时没调用模型当成退出。
- 每个普通入口 Session 在 MVP 中启动一个网络。已加入网络的节点不能通过再次启动网络绕过预算；完成后可开新 Session 启动另一网络。
- 默认 fresh context，不实现完整父历史 fork。
- 正常退出只保证完成已承接的工作；用户硬停止、硬资源限制、进程崩溃不提供这种保证。
- 普通回复消息不是任务完成。完成必须通过带任务标识的结果操作声明。
- 任务请求者已经退休时，合法任务结果仍应写入任务记录，不能逼迫独立后代永远等待一个已退出的请求者。原目标投递单独记为不可达，向网络入口发送一条有界的结果引用通知；不复活请求者、不改写任务来源。这是为避免结果丢失采用的 MVP 默认，不适用于转移旧提案投票权。

### 1.3 不在本版范围

不做拓扑图 Web UI、动态角色系统、全局智能调度者、信息素算法、复杂信誉评分、多数表决、全局任务 DAG、跨机器部署、自动合并代码工作区、自动切换模型和真实群体质量 benchmark。保留通用工具结果和运行状态，足够调试和使用。

## 3. Bundle 装配与模块职责

### 3.1 一个安装包，两个插件入口

目标 npm 包名为 `dsh-atn`，显示名可用 dsh-ATN。使用 ESM、编译后的 JavaScript 和类型声明，`package.json` 声明 `dsh.bundle.patch`，包含 `cordis.patch.yml`。

建议的正式目录如下；可以合理拆分文件，但不要新增与 MVP 无关的抽象：

- `src/index.ts`：ATN runtime 的 Cordis service 插件。
- `src/tools.ts`：模型工具和共同规则提示。
- `src/domain.ts` / `src/schema.ts`：持久数据定义和校验。
- `src/topology.ts`：纯邻居推导。
- `src/lifecycle.ts`：创建、恢复、正常退休、硬停止和资源所有权。
- `src/mailbox.ts`：持久入队、投递和去重。
- `src/proposals.ts`：固定审批名单与文档版本提交。
- `tests/`、`tests/fixtures/`：确定性行为、真实 Loader/profile、权限和恢复验证。
- `cordis.patch.yml`、构建配置、根 `package.json` 和 lockfile。

Bundle patch 插入 runtime 和工具入口，不替换用户的模型、sandbox、approval 或完整 preset 配置。服务插件与函数插件采用 Harness 支持的导出方式，不混用默认导出和函数插件命名导出。

安装可以增加 ATN 工具的可见性，但仅在用户要求使用 ATN 且模型显式启动网络时创建节点、写网络目标；不能因为安装插件就自动运行蜂群。其他 Session 不应产生 ATN 网络状态或模型请求。

### 3.2 深度复用 Harness

复用 Agent factory/loop、Session persistence、tool registry、scoped preset、权限机制和 `storageDomain`。不依赖 `dsh-subagent/internal`、不改核心循环，也不重写一套模型请求循环。

需要共享运行实例的 Harness 包放在 `peerDependencies` 并在 `devDependencies` 中为构建和验证声明对应版本；不要把 Cordis、Agent registry 等打成第二套运行实例。打包只包含正式运行产物、类型、patch、README、许可证及必要说明，不包含测试临时目录、原型依赖、上游源码或本地设置。

### 3.3 网络所有者和入口节点

runtime 在自己的稳定 Cordis scope 下创建和持有 ATN 工作节点，不使用出生者的 `agent.ctx` 作为资源所有者，也不通过 `parentAgent` 绑定它们的运行寿命。出生谱系单独持久保存。

注意 Cordis service 调用可能携带调用方作用域：把原型改为 Service 后，不能假定每次访问 `this.ctx` 都还是最初的网络所有者。参考上游 AgentLoop 保存稳定注入上下文的 holder 方式，明确捕获创建/恢复所用的 owner context，并通过真实模型工具调用验证所有权。只把 handle 放进一个 Map 不会修复错误的结构所有者。

用户正在交互的入口 Agent 是宿主所有，不是 ATN 创建的 handle。ATN 可以将其纳入网络并安装作用域内规则，但正常完成或插件卸载时不能擅自 `dispose` 宿主入口 Agent。

MVP 默认由入口节点承担面向用户的最终汇总。它与其他节点使用相同 ATN 操作，不垄断创建、投票或消息发送。它的特殊性仅是宿主交付入口和初始用户任务的持有者。

## 4. 最小模型接口

以下为推荐正式接口，不要求沿用原型的测试用参数名。返回结构化数据，UI/模型文案由 renderer 处理，不能要求调用者从自由文本猜 id。

| 操作 | 必要输入 | 语义 |
|---|---|---|
| `atn_start` | 简短目标、成功标准、共同约束 | 在当前普通 Session 初始化网络，建立初始任务，返回网络、节点和任务标识；不生成额外主管 |
| `atn_spawn` | 局部任务、必要上下文、可选寿命 | 创建同能力独立节点；id 由 runtime 分配，显示名称不是授权凭据 |
| `atn_send` | 目标、消息类型、内容；结果携带任务标识 | 区分 `task`、`note`、`result`，由 runtime 填写发送者；结果只可结清发送者自己的匹配任务 |
| `atn_peers` | 可选查询 | 默认返回当前四个邻居及有界摘要；查询返回少量候选，不改变审议邻居 |
| `atn_finish` | 可选退出说明 | 请求正常退休，不立即销毁，不等同于某个任务完成 |
| `atn_propose` | 基础版本、完整短文档替换内容、理由 | 建立不可变提案并固定当前有效邻居名单 |
| `atn_vote` | 提案标识、明确同意或反对、可选理由 | 按固定名单和真实调用者授权；同票重试幂等，不允许冒名代投或悄悄改票 |
| `atn_renew` | 请求延长的寿命、任务依据 | 仅在剩余任务和网络预算内续期，不能重置消耗或恢复已硬停止的网络 |

建议由 `atn_send` 的结果变体承载完成，不额外添加多 action 的万能管理工具。发给用户的最终结果需提供当前目标版本和可复查证据引用；运行时检查初始用户任务归属、其他正式任务及审议是否已结算、待发信箱是否清空，再原子记录交付与完成。

若完成条件未满足，拒绝完成操作并保留原任务状态，不把局部结果强行当成全局完成。机械检查不证明业务结论正确，汇总节点仍需对照成功标准提供实际证据。

完成后释放 ATN 自己的工作节点，不销毁入口 Agent；入口必须能正常收到该工具结果并生成最后回复，不能被“网络已关闭”的 pre-step 拦截误伤。新 ATN 写操作继续被关闭状态拒绝。

宿主级停止由可调用的 runtime 方法和一个不依赖模型继续推理的用户入口提供。若使用 Harness command，应遵循其 command registry；不能只提供一个需模型自己决定调用的停止工具。

## 5. 持久数据与一致性

### 5.1 最小记录

- **Network**：稳定网络 id、入口 Session、状态、配置/额度、当前目标及版本历史、下一条记录标识。
- **Node**：独立节点/Session id、`creator_id`、持久的 `selected_child` 路径、生命周期、租约期限、模型路由和 preset 身份、创建状态、权限种子来源。
- **Task**：id、持有者、请求者、描述、必要上下文、状态、显式结果及证据。
- **Mail**：id、真实发送者、目标、类型、关联任务或提案、正文、入队/回执状态。
- **Proposal**：id、提案者、基础版本、固定正文、理由、固定审批者、票、期限和终态。

不能用 Agent 的 `idle` 状态代替任务完成，也不能用当前邻居集合代替旧提案的审批名单。

### 5.2 采用 `storageDomain`

使用 schema 校验的网络持久域，建议 MVP 以单个网络记录作为一次原子更新单位，内部按字段持有上述有界集合。使用每网络串行事务及域的原子 `update`，避免跨多个记录写一半的伪事务。所有变更先持久化成功，再公布状态和成功结果。

这是有界小网络方案，不是高吞吐数据库设计。配置累计任务、提案、消息和文档容量上限；失效和终结记录不能为了省空间随意删除去重凭据。需要压缩或迁移时另做显式版本协议。

不直接读写用户工作目录中的可覆盖 JSON 文件，不把普通可编辑 Markdown 文件作为唯一授权来源。Markdown 可以是目标内容或展示形式，权威版本和修改依据由 runtime 管理。

### 5.3 创建与恢复

创建先持久保留身份/创建意图，再在网络作用域创建 Agent，完成 preset、权限种子和本地上下文安装后才发布可用状态并投递初始任务。失败需释放 handle 和容量，保留明确失败事实，不能留下“已创建成功”但没有节点的记录。

恢复不能像原型一样遇到 provisioning 就停止整个网络：检查持久创建意图与 Session 状态，能安全重建则完成；不能确认的标记失败并结算关联任务，不能重复生成另一个同身份节点或假称成功。

单进程中的 create、resume、delivery、retire 使用每节点唯一的激活所有者和串行控制，不能同时恢复两个同 Session handle。已完成或硬停止网络不能因重启恢复为 open。

插件重载/进程正常关闭可以释放内存 handle，但保留可恢复状态；用户硬停止是持久终态，两者不能混为一谈。

## 6. 拓扑与生命周期

### 6.1 邻居推导

起点是本节点持久记录。向上沿 `creator_id`，向下沿 `selected_child` 路径，跳过非 `active` 节点，各取最近两个 `active` 节点。返回中不能包含自身或重复节点；遇到循环或断裂数据明确失败，不静默构造替代图。

路径记录属于历史与连接依据，退出后继续保留。自动绕过 B 找到 C、D 不意味着重写 C 的出生者。所选路径到尽头先留空；没有规则授权自动改走别的分支。

第一个**成功发布**的子节点才初始化选择，创建失败不得占用这个位置。并发创建时用成功提交顺序裁决，不能让两个回调分别认为自己是第一个。

### 6.2 正常退出

生命周期至少区分：

- `provisioning`：不可接普通新工作。
- `active`：可接新任务和新审议，当前活动可以是工作或等待。
- `draining`：不接新任务/新审议；继续旧任务的结果和已分配的审议，当前拓扑绕过它。
- `retired` / 明确失败终态：不再驱动模型，保留记录。

请求退休的提交点与新任务/提案分配共享明确的先后次序。分配早于退出的工作仍归原节点；退出之后的新工作不能进入它。

当自身任务和所需审议义务结清、inbox/driver 安全结算后再释放 handle。已持久投票不要求节点等待所有其他票。不要在工具的 `execute()` 中等待销毁当前 Agent，会形成自等待。

正式 runtime 必须依靠事件与受控调度自动完成这些操作，不能依赖原型 CLI 每步调用 `settle()`。

### 6.3 寿命和停止

租约用真实时间和持久 deadline；逻辑时钟只用于测试。租约到期触发正常退出，不立即杀死尚有旧工作的节点。续期由任务需要驱动，受网络总期限和预算限制。

硬停止首先持久关闭新工作入口，取消/结算任务与未完成提案，禁止恢复、续期和迟到投票提交，然后中断并等待所有 ATN-owned handle 清理。清理超时/错误必须可见，不能只发 cancel 就报告已结束。

入口 Session 被用户明确中断或归档时应有清晰的网络停止路径。需要根据真实取消原因或宿主操作对接，不能把入口的自然 idle 误当成用户停止；也不能将一次请求失败自动扩大为无条件全网销毁。

## 7. 文档审议与模型输入

### 7.1 全体一致协议

提案提交时一次性固定基础版本、正文和有效邻居。至少有一个审批者才允许进入正常审议；提案者不自动算作自己的审批者。

票绑定提案 id，提案内容不可原地修改。全体明确同意后，在同一个提交操作中再次检查网络 open、提案未过期、基础版本仍为当前版本，随后持久化新文档和审批依据。

任一反对不通过；沉默和超时不通过；文档基础版本变更则提案 stale。修改内容、重新基于新版本提案，都需要新审批，不自动合并或继承旧票。

旧提案依据已固定名单授权，不依据实时拓扑。B 处于 draining 时仍可投旧票，但不能因为过去是邻居就投新提案。分配时点以持久记录为准，而不是审议消息送达的墙钟时间。

原节点崩溃时等待原身份恢复，或让提案到期后重新提出；不能把其票交给补位者。明确拒绝、过期、stale 和取消会解除尚无意义的审议义务，避免节点永久卡在 draining。

### 7.2 共同目标的上下文

创建/恢复时让节点获得完整短目标快照；后续请求只在版本变化时同步。实际读到的版本号和正文必须进入 Session 可回放输入，不只记录一个会变的文件路径。

遵循 `MessageSourceMap` 的类型扩展。当前 Harness 没有通用 `source.kind = plugin`：使用自己的明确来源类型，携带目标版本或消息/提案标识。

在 `agent/pre-step` 中包装 `next()` 的结果并保留既有字段；不能把内容偷偷拼到 provider 请求中。版本“已被节点看到”必须依据实际落入 Session 的输入，不能在异步准备请求之前提前更新缓存导致消息丢失。

更新不会追溯修改进行中的请求；下一次请求使用新快照。仅同步目标版本不唤醒全部空闲节点。

## 8. 消息与局部任务

信箱先持久入队，再投递；忙节点用安全步界，空闲节点按需唤醒。每目标串行，保持已承诺顺序；inbox 或历史存在相同稳定消息 id 时补回执，不重复插入。

任务赋予、结果结算和相关 outbox 记录应在同一次网络更新中生效。先标记任务完成、后面发送失败却永久丢结果，不算正确实现。若原请求者已退休，任务结果与证据仍保留；原目标投递明确记为不可达，并对入口排入有界的结果引用通知，不能保留一个永远无法送达的 queued 项阻塞整个网络完成。通知保留真实产出者和原请求者，不冒充原请求者或人类。

对外清楚区分 queued、目标已持久接收、业务结果已完成。节点不需要对每条消息进行礼貌确认，不能建立“回执触发回执”的唤醒环。

`draining` 可以接已有任务的关联结果和旧审议，但不能接新任务。网络完成/硬停止和目标退休之后的发送要明确拒绝或结算失败，不静默无限排队。

恢复时重放 queued-minus-receipted；投递确认检查目标 Session 的持久输入与已记录用户消息。文档同步、普通消息、任务和提案来源分开，避免被当成人类新授权。

发现工具默认只返回局部邻居；显式查询才给少量任务相关候选，不泄露其他网络或节点的完整对话。通信不自动改变审批资格。

## 9. 权限与能力继承：本轮重点

同能力不等于子节点拥有新的宿主权限。初始化时继承实际父节点使用的模型路由和 preset，保持 ATN 操作集合一致，但执行权限只能保持或收窄。

优先复用上游公开 helper：

- `parentAgentOptionsForDelegation` / `resolveChildAgentOptions`：从实际请求配置继承模型选项，避免偷偷回到默认模型。
- `captureDelegatedPolicyOverrides` + `appendDelegatedPolicyOverrides`：创建前捕获、创建时记录权限种子，特别是子节点不能自行发起权限升级。
- `applyChildComposition` / `agentPresets.composeFrom`：fresh 创建时复用实际 preset revision；这不要求使用父节点作为资源所有者。
- `agentPresets.mount`：冷恢复时按持久 preset 身份重建；不要要求创建者仍然是 live Agent。已记录的权限状态保持，不在恢复时重新从一个更宽松的节点继承。

这些 helper 不意味着全部整合问题已经解决。要在真实权限插件装配下证明：同一个受限操作对 ATN 子节点仍被拒绝，节点不能修改自己的权限、冒充发送者或把 peer 消息当作人类批准。不能通过把所有请求都标记为 `user` 来绕过审查。

有 preset 的组合若无法正确继承，创建应明确失败，不能静默用默认 preset。没有 preset 的合法组合可以依赖其原有全局工具配置。安装 ATN 不应把所有 Session 变成 full access。

网络预算只对 ATN 持有的节点负责。原生其他委派工具或可执行用户代码可能绕开这层调度；MVP 应对已知替代委派入口作一致限制，或明确暴露并在 README 说明限制范围。不能声称一个工具计数器限制了宿主所有任意模型调用。

## 10. 限额和配置

把可变参数集中放在 Cordis Config，验证正整数/范围关系。推荐初始默认值仅是可调整实验配置，不是用户额外制定的规则：

| 参数类别 | 建议初值/规则 |
|---|---|
| 最大驻留工作节点 | 8；provisioning/draining 仍占容量 |
| 每网络累计节点 | 32；释放并发槽不重置累计值 |
| 累计正式任务 / 提案 | 各 256 / 64，达到后明确拒绝 |
| 每节点待发消息 | 64，另设累计保留上限 |
| 单条完整消息 / 目标文档 | 各 8192 UTF-8 bytes，含 envelope 后检查消息大小 |
| 默认租约 / 最大单次续期 | 5 分钟 / 30 分钟 |
| 网络硬期限 | 60 分钟，可配置 |
| 提案期限 | 2 分钟，可配置 |
| 模型工作额度 | 明确计数单位；若按 admitted step 限制，就叫 step budget，不冒称 HTTP 请求或 token 预算 |
| 关闭与重试 | 有界超时、有界退避，不在一次暂时失败后无限忙循环 |

不要把 `maxTokens` 当作总费用限制。若没有覆盖请求重试、辅助模型调用和请求前 token 预留，README 必须直说计量范围。
