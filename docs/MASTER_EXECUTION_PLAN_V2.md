## 2. 跨阶段共享不变式（任何阶段违反即整体失败）

1. **零真实模型调用**：全程不使用外部/付费模型；脚本模型仅用于结构验证。**不主张**任何正确率、效率、吞吐、成本、延迟收益。
2. **先红后绿**：每个阶段先写测试/断言、跑出红灯并把原始输出留档到 `docs/execution-evidence/<阶段目录>/`，再改生产代码；不得先实现再补测试，不得把未跑过的路径写成已通过。
3. **不放宽既有契约**：14 条出站通道、16 个公开拒绝码语义、拒绝原子性（不追加消息、不消耗地址、不改权重/步数、不留脏数据、不产生邮件或唤醒）、持久化 domain 仍为 1——一条都不许放宽。
4. **模型工具面不变**：本轮**不得新增、删除或重命名模型工具**，不得给既有工具加参数（§8 的过滤必须是**宿主侧、对模型透明**的：被过滤的消息对模型等同于不存在）。因此 `tests/integration/fixed-context.test.ts` 的 7,956 / 5,910 字节与八工具清单必须保持不变；若有任何变化，视为越界并停止。
5. **新增读取面必须登记**：任何新读取路径都要同时更新 [`THREAT_MODEL.md`](THREAT_MODEL.md) 的 `B-*` 判据与 [观察权限契约](OBSERVER_READ_AUTHORIZATION.md) 的权限表，并声明其 principal / resource / action；不得靠版本号比较推定能力，不得自造描述符字段。
6. **授权模型唯一**：读侧权限只能沿用阶段 §4 已建立的 principal/resource/action 模型；不得并行发展第二套判定。消息权重**永不**授予权限。
7. **发现路径唯一**：`atn_status` 的文档/主题仍由宿主 custody + descriptor 反向派生；任何阶段都不得让新能力成为第二种发现来源。
8. **声明同步**：每个阶段结束都要更新受影响的 README、`docs/ADAPTIVE_TOPOLOGY.md`、通道审计、`DECLARATION_AUDIT.md` 与 `docs/README.md` 索引；不得把未测试内容写成已通过。

## 4. 阶段 1：§6 跨网络引用与地址命名空间补证

**目标。** 证明"网络是业务分区键"在**全部四类标识**上成立，并把"业务分区"与"读取授权"分别报告——**不得**由分区推出租户认证。

**现状。** 全部状态按 `networkId` 隔离、每网络独立串行 mutation 队列；已有 REVIEW-02 级别的"跨网络同号节点独立停止"证据。**未覆盖**：substrate 引入的 `msg:<n>` 网络局部地址空间，以及观察/导出在"指名另一网络"时的行为。

**必须覆盖的矩阵（纯结构 + 真实 live Agent/RPC 两层，缺一层即判未完成）。**

| 用例 | 期望 |
|---|---|
| 两个网络各自存在 `msg:1`／同号 nodeId／同号 taskId | 各自解析到**调用者自己的网络**；不得一概按外部引用拒绝，也不得跨网命中 |
| `task:` / `artifact:` / `msg:` 引用指向另一网络存在的同名标识 | 拒绝（`ref-unresolved` 或 `ref-not-visible`，按既有优先级），且**不泄漏**对端是否存在 |
| 观察快照按 sessionId 取数、而该 sessionId 属于另一网络 | 与"未知会话"行为一致（授权后返回 null／拒绝），不得返回对端内容 |
| `exportSubstrate(networkId)` 传入另一网络的 id | 行为必须在威胁模型 §B-HOST-EXPORT 的**书面前提**内可解释（当前前提：宿主可信、无调用者校验） |
| 两个认证主体分别读各自 session | 各自只看到自己的网络；交叉指名被拒 |
| 本地重名标识 | 解析到调用者网络，**不得**被当作外部引用误拒 |

**验收。** 新增集成用例全绿；若发现任何跨网络可达路径，**停止本阶段**，先按"先红后绿"修复并在报告中逐条列出可达路径与修复依据。

**风险与红线。** 身份绑定必须走真实运行路径，不能只做纯计算枚举。报告中**分别**给出"业务分区判定"与"读取授权判定"两张表；验证前不承诺"网络即租户"。

**证据。** `docs/execution-evidence/round-v2-phase1/`：红灯、绿灯、矩阵结果表、发现的缺陷（若有）与其修复留档。

## 5. 阶段 2：§8 读侧可见性（need-to-know 分区）

**目标。** 把保管层从"写侧声称校验"扩展到"读侧可见性"，**复用** §4 既有的授权模型与 custody 策略来源，不新增第二套判定。

**现状。** 写侧准入已交付（`ref-unresolved` / `ref-not-visible` / `ref-not-owned` / `custody-unavailable`）；**读侧无分区**：能调用 `atn_search` 的节点可检索全网消息（仅作者与权重被隐藏）。

**设计要求（全部为强制项）。**

1. **宿主侧、对模型透明的过滤**：策略由宿主提供（形如现有 `defineCustodyPolicy` 的**同步**解析器，输入调用节点与网络记录，输出可见范围），**不得**新增模型工具或工具参数（共享不变式 4）。
2. **过滤即不存在**：被过滤的消息在 `search` 中不出现（不占 k、不参与排序）；`visit` 一个被过滤的地址必须返回与**不存在地址完全相同**的错误与措辞——不得让模型或调用方区分"不存在"与"不可见"（存在性泄漏）。
3. **不可旁路**：过滤后，`citedBy` 计数、权重更新、证据链闭包与 `refs` 准入都不得泄漏被过滤消息的存在、文本或数量；引用一条自己看不见的消息必须被拒绝。
4. **确定性可重放**：过滤结果必须是持久记录 + 策略的纯函数，与阶段 §4 的整数排序一样可逐字节重放；策略缺失时行为必须明确（见第 5 条）。
5. **默认姿态（需用户批准）**：建议 `substrateReadPolicy` **默认关闭**（无策略时保持现行"全网可读"语义，即论文语义），由宿主显式安装策略后才生效；开启与关闭都要有对照测试。**不得**在没有宿主映射的情况下自行发明可见性规则。
6. **偏离清单更新**：论文假设数据存储全网可读，本能力构成**第 8 条偏离**，必须在 [Substrate 实施报告](SUBSTRATE_COORDINATION_INTEGRATION_IMPLEMENTATION_REPORT.md) 的偏离表中新增一行并说明可关闭性。

**验收。** 单元与集成测试覆盖：可见/不可见集合确定性、`visit` 两种错误的**不可区分性**（对错误文本与错误码同时断言）、引用不可见消息被拒、`citedBy` 与证据链不泄漏、策略关闭时与现行行为逐字节一致、冷加载与重放一致；**过滤对固定上下文零影响**（7,956/5,910 不变）。

**证据。** `docs/execution-evidence/round-v2-phase2/`：红灯 TAP、绿灯 TAP、重放输出、开启/关闭对照。

## 6. 阶段 3：§5 宿主 custody 一致性套件

**目标。** 交付一个**宿主可以带走、独立运行**的套件，把"可证明隔离"从声明变成可判定。

**必须覆盖。**
- 持有即放行 / 未持有即拒绝；
- **14 条出站通道逐一**，含第 14 条 `publish`；
- 三类引用准入：`msg:`（存在且早于本条）/ `task:`（存在且可见）/ `artifact:`（在真实保管集合内；未装策略时必须拒绝 `custody-unavailable`）；
- 可选传输字段（`messageId` / `dependsOn` / `retryOf`）不得成为隐式隧道；
- 拒绝**原子性**：不追加消息、不消耗地址、不改权重、不改步数、不留脏数据、不产生邮件或唤醒；
- 容量语义：`substrate-full` 时**绝不驱逐**既有消息；
- 阶段 2 的读侧策略面（若已落地）：策略缺失、策略抛错、策略返回异步值三类行为。

**交付形态（三条缺一不可）。**
1. 套件本体与运行入口（例如 `tests/conformance/` + 一个可执行入口），**只用公开 API 与宿主自报的 claim 语法**，不得依赖仓库内部结构；
2. 接入指南：宿主要为自己的策略实现哪几个函数、怎么跑、失败信息怎么读；
3. **负例实现**：至少两个故意不合格的宿主策略 fixture（例如"未持有也放行"、"异步策略"），证明套件确实能红灯——否则套件自身不可信；
4. 发布面：若套件要随 npm 包交付，必须进入 `package.json` 的 `files` 白名单；若决定不随包发布，必须在指南中写明获取方式。**不得**让套件只存在于本仓库而宣称"宿主可运行"。

**验收。** 套件对本仓库 `examples/information-boundary.ts` 的示例宿主全绿；对每个负例 fixture 精确红灯且失败信息指明违反的契约名；`npm test` 全量仍绿。

**风险。** 套件若隐含未公开假设，会把宿主集成变成猜谜；发现这种情况必须收窄套件而不是放宽契约。

**证据。** `docs/execution-evidence/round-v2-phase3/`：套件输出（绿）、每个负例的红灯输出、接入指南链接。

## 7. 阶段 4：§9 多网络（舰队）观测面

**目标。** 给运营者一个跨网络视图：网络清单、健康、**拒绝计数**、预算消耗、substrate 容量。**只读、不唤醒、零额外 token**。

**前置与授权（硬性）。**
- 必须沿用 §4 的 principal / resource / action 模型：新增独立资源与独立 action（例如 `atn-fleet` + `atnObserver/fleet`），**默认不授予**任何主体；
- 权限表、授予前必读事项与"未知网络不泄漏存在性"规则必须写进 [`OBSERVER_READ_AUTHORIZATION.md`](OBSERVER_READ_AUTHORIZATION.md) 与 [`THREAT_MODEL.md`](THREAT_MODEL.md) 的 `B-OBSERVE` 行；
- **不得**把舰队视图建在 owner bypass 上，也不得默认复用 `atn-observation` 的单会话别名。

**拒绝计数（先设计口径，再实现）。**
- 只加**有界计数**（按拒绝码分桶、每网络有上限），**不得**记录被拒内容或任何载荷片段——内容最小化是硬约束；
- 计数**不是**审计 journal：`docs/ROADMAP_NEXT_DIRECTIONS_V2.md` §7 的完整审计存证仍是设计阶段的事，本阶段不得宣称已具备合规日志；
- 网络记录新增字段为可选增量，domain 保持 1，旧记录可冷加载。

**UI 要求。** 复用既有 `atn-network` tab 与顶栏回退的**既有分区模式**（不新增 tab 注册项、不改侧栏契约）；跨网络聚合必须遵守与单网络视图相同的只读、有界、失败降级规则。

**验收。** 授权矩阵测试：未授予主体调用舰队端点被拒（先留红灯）；授予后只返回被授权范围的网络；两主体交叉验证互不可见；快照字段严格 schema 校验；`smoke:visualization` 在真实浏览器验证跨网络分区渲染。

**风险。** 这是**最容易反噬 §3/§4 成果**的一项：聚合视图天然跨租户。若无法用既有授权模型表达"运营者可看哪些网络"，**停止本阶段**并把舰队面退回路线图，不得自造第二套授权。

**证据。** `docs/execution-evidence/round-v2-phase4/`：红灯、授权矩阵表、浏览器预览输出与截图、计数上限测试。

## 9. 停止条件（遇到即停，不得绕过）

2. 阶段 2 的过滤无法做到"确定性 + 可重放 + 不可旁路"三者同时成立——此时**删掉该能力**，不得降低其中任一项。

4. 阶段 3 的套件若必须依赖非公开 API 才能覆盖契约——收窄套件范围，不得扩大公开面或私开后门。

6. 任何阶段若需要真实模型调用来**证明**其结论——停止并改写结论为"未验证"。

## 12. 需用户批准的三个决策

1. **阶段 2 的默认姿态**：建议读侧策略**默认关闭、由宿主显式安装**（保持论文语义，避免插件自行发明可见性规则）。
2. **一致性套件的发布形态**：建议**随包发布**（进 `package.json` 的 `files`），否则"宿主可运行"只是口头承诺；若选择不发布，指南必须写清获取方式。
3. **舰队视图的授权入口**：建议**默认不授予**任何主体，且必须显式配置；不接受"沿用 owner bypass"或"复用单会话别名"作为默认。

未批准前，阶段 2 与阶段 4 的相关实现不得开工（阶段 0/1/3 不受影响）。
