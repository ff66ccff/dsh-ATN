# dsh-ATN 等预算对照基准实施说明（第 9 轮）

这份文档交给实现代理执行。**本轮不做机制消融，不做拓扑绑定。** 目标是回答 README 目前写着"没有证据"的那个问题：**同等总预算下，ATN 相比单智能体和 Harness 自带 agent team，是否更准、更快、更省。**

实现代理必须先读完第 0、1、2 节再动手。第 2.1 节是本轮唯一的硬约束。

## 0. 为什么换问题

### 0.1 已有两条独立证据线，都指向同一结论

| 线 | 任务族 | 实际结论 |
|---|---|---|
| pilot（2026-10-04） | `ledger-reconciliation` 等真实任务 | `single`／`independent-pool`／`native-team`／`atn-adaptive` 在 deepseek 上**全通过**；space-bunny 上 `single` 通过而两个 ATN 臂**失败**。scope 自述"无统计或因果拓扑优势主张" |
| 拓扑线（10-05 → 10-07） | `shifting-evidence` 合成链 | 构造性参考 **0 次模型调用**解出；五臂 25 次、简化研究 56 次，完成率臂对全部不可区分 |

### 0.2 三条硬事实

1. **合成任务不需要智能。** 确定性脚本 0 次模型调用解出，任何正向结果只能证明协议合规。
2. **合成任务不分布认知。** 提示词明写 "The entry alone assembles the chain and submits checkpoints"；helper 只"每阶段读一次、发布一次、应答请求"。全部推理在入口一个节点内。
3. **因此消融不可能有差异。** 被拆掉的机制本来就不承重。

### 0.3 pilot 的限制，而不是 pilot 的结论

pilot 已经跑过正确的对照，但它的配置无法支撑任何结论：

- **n = 1**，每个模式每个模型只有一次。
- **`maxAgents = 3`、`maxCalls = 16`、`timeoutMs = 180000`。** 单智能体在 16 次调用下根本没有被压到——**并行只在工作量相对单智能体预算足够大时才可能产生差异，而 pilot 的工作量太小。**

所以 pilot 不能证明"没有优势"，只能证明"在这个规模下没测出优势"。**本轮把同一个对照重跑成有功效、有规模、等预算的版本。**

### 0.4 本轮不重复发明对照

四个臂**已经存在**（`experiments/run.ts:55` 的 `PILOT_MODES`），遥测已采集每次调用的 `inputTokens` 与 `startedAt/completedAt`。本轮是**放大并等预算**，不是新建机制。

## 1. 本轮要回答的问题

> **Q1 正确率**：等总预算下，四个臂是否可比？
> **Q2 墙钟**：并行是否真的更快？
> **Q3 峰值上下文**：每个智能体承受的最大单次输入是否更小？
> **Q4 总成本**：总 token 与协议交互是否可比？

产出：每个臂一组区间，以及一句可以写进 README 的话——或者"未观察到优势"。

**空结果是合法且重要的结果。** 本轮不得为了让任何一臂显得更好而调整任何条件。

## 2. 设计条件

### 2.1 总预算必须相等（本轮唯一硬约束）

ATN 使用 N 个智能体 × 每节点 S 步。那么 `single`、`independent-pool`、`native-team` 的**总预算都必须等于 N × S**：

- `single`：一个智能体，预算 **N × S**；
- `independent-pool`：N 个智能体，总预算 **N × S**（每个 S）；
- `native-team`：N 个智能体，总预算 **N × S**；
- `atn-adaptive`：N 个智能体，总预算 **N × S**。

**必须有一个测试断言四个臂的配置总预算相等**，并在报告中写出每个臂的实际分配与实测消耗。

不做这件事，结果会退化成"算力多的一方赢"，毫无价值。**这是上一轮 pilot 没有明确处理的量。**

### 2.2 只改臂，不改别的

同一任务、同一 fixture、同一模型、同一文档访问权限。臂之间唯一的差别是协作方式。

### 2.3 不得制造 `single` 的失败

不要通过把任务做得超大、把 `single` 的预算压小、或给 `single` 更差的工具来制造"单智能体失败"。

**正确做法：把工作量放大到"并行可能有用"的量级，然后给每个臂相同的总预算。** 让数据决定，不要设计结果。

判断"工作量是否够大"的可操作标准：**在预注册的 S 下，`single` 的实测上下文应当出现明显增长（例如峰值输入接近其可用上限的一半以上）。** 若 `single` 全程游刃有余，说明规模仍不够，本轮无信息量。

### 2.4 允许分工

上一轮的 `topologyBinding` ACL 禁止转发（"no forwarding, relaying"）——那是为隔离拓扑通道设计的，**本轮不适用**。本轮测的是协作，必须允许节点之间传事实。所有臂使用同一套 ACL。

### 2.5 任务必须真正可以并行

任务必须由 **K 个独立的子问题**组成，每个子问题可以由不同节点独立推进，最后需要合并。当前单链任务（4 个事实）不满足：它太小，且提示词强制入口独占。

## 3. 臂（阶梯设计）

| 臂 | 并行 | 协调 | 说明 |
|---|---|---|---|
| `single` | 无 | 无 | 单智能体，总预算 N×S |
| `independent-pool` | 有 | 无 | N 个智能体各干各的，不交换信息 |
| `native-team` | 有 | 通用 | Harness 自带 agent team 原语 |
| `atn-adaptive` | 有 | ATN | 全部机制开启 |

这个阶梯是**本轮的核心设计**：它把"并行"和"协调"分开。

- 若 `single` ≈ `independent-pool` ≈ `native-team` ≈ `atn-adaptive` → 并行和协调都不带来收益。
- 若 `independent-pool` 明显优于 `single`，但 `atn-adaptive` ≈ `independent-pool` → **收益来自并行，ATN 的协调层没有额外贡献**。
- 若 `atn-adaptive` 明显优于 `native-team` → ATN 层有独立贡献。

**三种结果都必须能被报告出来**，不得只报告对 ATN 有利的那种。

## 4. 任务

在 pilot 任务族（`experiments/tasks.ts`）上放大，不新建机制：

- 由 **K 个独立子问题**组成（建议 K = 8），每个子问题需要检查自己的证据并算出一个局部结果。
- 最终答案需要**合并**这 K 个局部结果，宿主按 fixture 精确校验。
- 建议 N = 16，每节点 S 由预注册决定；N×S 即为各臂总预算。
- 保留 pilot 任务的真实性：纯文档 + 整数计算 + 精确答案，不引入需要主观判断的评分。

验收测试：

- 放大后的 fixture 满足：子问题相互独立；每个子问题有唯一正确答案；合并步骤不可省略。
- **每个臂都必须验证可解**（零模型调用的构造性运行，或等价的书面论证）。这是**配置正确性检查**，不是本轮的对照臂——本轮的对照臂是另外三个模式。

## 5. 指标

### 主指标

| 指标 | 定义 | 口径 |
|---|---|---|
| **正确率** | 答案与 fixture 精确一致 | Wilson 95% 区间 |
| **墙钟** | `completedAt − startedAt` | 报告**中位数与四分位**，不用均值（长尾） |
| **峰值上下文** | 单次调用 `inputTokens` 的最大值（每运行、每智能体分别报告） | 未知 usage 保留未知 |
| **总 token** | 已知 input + output 之和 | 已知/未知分列；未知不得记零 |

### 保留指标

协议交互数、传输字节、入口步数、失败消耗——口径与上一轮一致，失败与完成分开列。

### 必须写明的限制

- **墙钟受共享 API 服务延迟与限流影响**，并行调用可能被限流，不能单独当作效率证明。
- 峰值上下文只说明"每个智能体承受多少"，不说明质量。
- `native-team` 使用自带传输，与 ATN 的邮件／白板传输不同，这是固有差异，必须写明而不是抹平。
- 全部 `causalClaim=false`。

## 6. 必须保留的既有语义

- 入口 Agent 由宿主拥有；完成、停止、退休都不 `dispose` 入口。
- 网络记录是唯一原子持久化单元；"检查 + 修改"在同一 mutation 临界区内完成。
- 边是单向的；出生谱系只作追溯。
- 工具身份、发送者、投票者取自真实 live Agent。
- 同伴文本不构成人类授权；请求者评价不构成宿主验收。
- 同能力原则：限制的是信息可达性，不是能力。
- `stepBudget` 不得被宣称成 token、HTTP 请求或费用上限。
- 正向事实流审计继续对全部真实运行执行。

## 7. 不要做的事

1. 不新增模型工具，不新增机制。
2. **不为制造某一臂失败而调整任务或预算。**
3. 不让任何一臂获得其他臂没有的工具或信息。
4. 不用墙钟单独支持收益主张。
5. 不删除失败样本、不补跑成功样本、不挑选 seed。
6. 不把 `single`／`native-team` 的失败写成 ATN 收益。
7. 不删除已有测试，不降低断言强度。
8. 不在预注册的预算与 seed 确定前开跑。

## 9. 决策门与发布

0.4.1 已发布，本轮**不阻塞发布**。

本轮同时是**研究线的决策门**：

- 若 `atn-adaptive` 在等预算下**明显优于** `native-team` 或 `single`，则找到了可写进 README 的主张，走 0.5.0 并附区间。
- 若 `atn-adaptive` ≈ `native-team` ≈ `independent-pool`，则**收益来自并行而非 ATN 的协调层**，README 应据此改写，研究线应转向或停止。
- 若四臂全不可区分，则本轮无信息量，应先解决规模与功效问题再谈收益。

**无论哪种结果，都不得把本轮写成 ATN 优势证明，除非区间支持。**
