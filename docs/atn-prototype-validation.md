# dsh-ATN 原型验证报告

## 结论

2026-10-03，最终版本的原型连续两轮从全新临时目录运行，**每轮通过 19 个检查点，执行 139 次脚本化 Harness 模型请求，真实模型调用为 0**。TypeScript 类型检查通过。

已验证的核心路径：**独立节点递归创建 → 局部发现与通信 → 全邻居审议 → 中间节点退出新拓扑并向外补位 → 原节点完成旧任务和旧审议 → 释放原节点而后代继续工作 → 恢复持久状态 → 最终交付和清理。**

这个结果支持继续做正式插件的最小纵向实现，但不证明真实模型的群体效果，也不等于完整产品可用了。

## 验证环境和方法

- Node.js `v24.19.0`，Windows 本地运行。
- 已发布的 `@deepseek-ai/dsh-*` 内核包锁定为 `0.2.0-rc.2`，Cordis `4.0.4`，依赖安装不运行生命周期脚本。
- 上游分析基线：`639ed015397290b3745d163aafe02ffee4aa3f84`。执行时使用同版本 npm 构建，不是本机编译源码仓库；上游 checkout 未被修改。
- 真实 Cordis 作用域、Agent factory/loop、工具执行、Session 日志与 JSONL 持久化；仅模型决策由确定性脚本替代。
- 同一个模型替身和相同的七个原型工具用于所有节点，没有按节点授予不同角色能力。
- 网络记录保存在标记为可丢弃的原子 JSON 临时快照中；节点上下文保存在真实 Harness Session 中。
- 每次执行新建临时目录；恢复检查会在一轮内关闭整个内核，再从相同临时目录重建。

这是进程内内核装配实验，不是 `dsh` profile/bundle 安装测试。原型执行器会驱动检查点并收敛运行状态，不是生产级后台调度器。

| 独立创建 | A 创建 B，B 创建 C，C 创建 D，D 创建 E；新分支 X 也可创建 Y |
| 同构能力 | 实际请求中的工具名称集合一致，没有 Lead-only 工具 |
| 四邻居 | C 初始邻居为 B、A、D、E；新建 X 不替换 A 首先选择的 B |
| 非对称邻域 | X 以 A 为上游，但 A 的下游保持 B、C，不自动纳入 X |

| 版本冲突 | 另一份基于旧版本的提案即使全票赞成，也只能变为 stale，不能覆盖新版 |

| 等待新任务 | C 完成初始任务后保持 active，可接受并完成第二个任务 |
| 持久恢复 | 重建整个内核后，目标、部分投票、任务、路径和请求计数保留，B 不被错误复活 |
| 消息去重 | 模拟目标已持久接收、发送方丢失确认；恢复后补确认，目标历史中仍只有一条消息 |

## 验证明确了哪些实现要求

### 1. 网络作用域必须真正拥有 Agent

原型通过网络插件的 `ctx.agents.create()` 创建节点，不通过出生者的 `agent.ctx`，也不传入运行时 `parentAgent`。出生者只保存在网络记录中。实际释放 B 后，其后代仍存活，验证了这条所有权接缝可行。

### 2. 旧提案按冻结名单授权，不能按当前邻居授权

B 已经从 C 的当前邻居集合消失，但仍可以对分配给它的旧提案投票，同时不能对新提案投票。只有把提案名单和实时拓扑分开才能满足这两个条件。

### 3. 退出节点的路径记录不能一起删除

向下补位需要继续沿 B 保存的所选路径找到 C、D。释放 Agent 不等于删除出生和分支记录；恢复后也必须保留这些记录。

### 4. “已收到”和“已完成”必须分别记录

原型使用独立任务状态、审议义务和消息回执。空闲 Agent 仍可有未完成任务，不能据此退休或宣布整个网络完成。

## 已知边界与不能外推的结论

1. **没有真实 LLM 实验。** 拆分、发现、赞成和反对都是预先安排的 fixture。尚未验证自然决策、任务质量、通信成本或是否优于单 Agent。
2. **没有 profile、正式 bundle 或权限继承验证。** 原型没有安装 shell、工作区文件编辑、真实模型或审批/沙箱插件；同构工具和身份检查通过，不代表正式部署授权已经正确。
3. **恢复是可控关停后的重建。** 丢回执用故障开关模拟；没有强杀进程、断电、磁盘损坏或多进程并发测试，也不承诺外部副作用恰好执行一次。
4. **创建过程恢复未实现。** 若恢复发现仍处于 provisioning，原型明确失败，而非假装恢复成功。
5. **不是生产调度器。** 演练在步骤间等待工作结算并释放节点；租约和提案期限使用可推进的逻辑时钟，没有验证真实长时间定时调度。
6. **临时存储不用于正式插件。** 网络状态整份同步写入，仅用于验证原子状态转换；正式的存储、迁移和吞吐需要另做。
7. **路径尽头留空。** 向外补位不跨到其他未选分支。当原路径已无有效节点时，即使其他分支还存在，也不会擅自替换。这沿用讨论稿的暂定边界规则。
8. **验收内容是 fixture。** 交付门控验证了未完成任务不能被当作成功，但真实任务还需要实际测试或其他外部证据。


```bash
npm --prefix prototype run explore
```

```bash
npm --prefix prototype run typecheck
```
