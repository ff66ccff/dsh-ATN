# 拓扑测量改造后的真实模型验证（2026-10-05）

本轮通过真实 DeepSeek Harness 内核和 `dsh-opencode-go` 完成 6 次校准：DeepSeek V4.1 Flash 和免费 Space Bunny 均为 2/2 答案通过，免费 LongCat 2.5 Preview 两组均在 600 秒期限内未交付。三个模型均未通过主实验校准准入，未启动扩展矩阵。先完成 Phase 0 零模型参考验收，再按预先保存的计划运行成本校准；所有成功、失败和不完整 usage 样本均保留。

机器可读结果见 [topology-measurement-20261005.json](../experiments/results/topology-measurement-20261005.json)。离线汇总工具为 [summarize-topology-measurement.mjs](../scripts/summarize-topology-measurement.mjs)，不导入 provider、不调用模型。

## 条件与范围

- 模型精确路由：`space-bunny-free`、`longcat-2.5-preview-free`、`deepseek-v4.1-flash`。执行前检查实时目录，前两者参考价格字段全为零；DeepSeek 是用户指定的非免费模型。
- 任务 `shift-ledger-1`，每种模型各跑一次 `atn-no-rewire` 和 `atn-adaptive`，共 6 次校准。禁主动重连仍允许运行时修补失活邻居。
- 8 节点、相同四邻居初始环、每节点 16 步、最多 128 次模型调用，每次输出上限 8,192 token，单次运行期限 600 秒。
- 显式 `--calibrate`，观测 token 阈值为 `null`。此次是测量实际成本的校准，不是已采用“成本 × 2”安全网的主实验。
- 默认 `self-organized` 恢复；宿主不指定备份。失效槽位的恢复义务进入 orphan 通道，认领成功才获得读取权限。未运行独立的 `preassigned-backup` 对照臂。
- 普通任务上限 128；每节点待发邮件 32、普通保留邮件 128、消息与 ATN 共享目标文档上限各 8,192 字节。文档限额不是 `read_document` 证据文件大小限额。运行时结算保留容量独立于普通邮件限额。
- 全部初始分片读取后，发布第二阶段文档 id 清单、更正证据并使 slot 7 失败。提示词要求只传四个账户小计，不传原始条目。
- 顺序为 DeepSeek 禁重连→自适应、Space Bunny 禁重连→自适应、LongCat 自适应→禁重连；各运行串行，运行期间未修改捕获的源码。

运行依赖为 Harness `0.2.0-rc.2`、`dsh-opencode-go@0.1.20`。本轮验证内核集成和真实 provider 调用，未验证桌面 UI 或发布包安装。宿主仍初始化分片及出生任务，因此后续认领恢复任务不等于已经证明涌现分工。

## 零模型前置门

执行真实模型前重新运行 `npm run experiment:reference`。四个策略均通过 oracle，模型调用数为零；每个 ATN 运行也先执行同限制的 hub 可行性检查。

| 参考策略 | 消息 / 跳数 | 最大节点上下文字节 | 最大节点动作数 |
|---|---:|---:|---:|
| hub | 22 | 1,346 | 11 |
| ring-gossip | 68 | 3,811 | 14 |
| tree-aggregate | 27 | 1,420 | 12 |
| adaptive | 67 | 4,633 | 15 |

hub 总载荷为 7,873 字节。四策略基线直接调用真实 ATN API 并记录动作数；逐次 hub 闸门将每次动作计入保守的步数代理。它证明这些限制下存在可交付策略，不保证模型的耗时、输出长度或调用行为。

## 机制验证与剩余问题

本轮观察到了实际恢复认领，且认领者能读取失效槽位的初始与更正文档。这与此前只有指定备份能读取、认领没有实际用途的条件不同。所有判定均结合工具结果、持久 retry 链和文档读取轨迹，不把“尝试 claim”计作成功。

六组均完成有效故障干预、8/8 初始与更正分片读取和失效分片恢复；共尝试认领 30 次，确认 7 次，其中 6 次是恢复任务、1 次是普通任务。131 次运行时反馈快照全部满足至少 3 步间隔，未包含 `steps=` / `remaining=` 易变文本。共 10 个工作节点因步数预算退休，六个入口均未退休，没有创建或认领 delivery 任务，因此此次真实调用没有覆盖交付接管；已有确定性测试不能替代这一缺失的模型场景。

四个成功运行中，DeepSeek 禁重连通过原生 `atn_finish(scope='network')` 完成交付，网络状态为 `completed`。DeepSeek 自适应及 Space Bunny 两组通过实验提交捕获答案，提交时网络仍为 `open`；答案 oracle 通过和完整协议关闭是两个独立结果。

聚合提示词未形成可靠约束。Space Bunny 禁重连的消息 `m18-p1-slot6` 包含 slot 6 的全部 12 行 id 和金额，按账户写成文字算式；自适应的 `mail-40` 同样包含 slot 3 的全部 12 行 id 和金额。它们不是只传四个小计。DeepSeek 与 LongCat 也有包含行标识或更正细节的消息，但仅凭标识扫描不能断言每条都包含完整原始行。汇总保留标识扫描结果，完整分片判断经过正文核对。

其他预算也确实影响了运行：DeepSeek 禁重连遇到过一次普通保留邮件限额拒绝，随后仍成功交付；LongCat 两组均触发 600 秒期限，并出现上述步骤及回合截断。这些都应作为失败或干扰信号保留，因此不能宣称本轮只存在“每节点步数”一个实际约束。

服务错误与任务错误分开统计。LongCat 自适应记录 9 次 `TRANSPORT` 终止和 3 次流空闲 `TIMEOUT`；Space Bunny 禁重连记录 8 次连接错误和 2 次请求超时，最终仍成功。LongCat 禁重连没有记录 provider error，仍因期限停止，因此不能把两组失败都归因为外部服务。工具参数缺失、非邻居发送、认领条件不满足另记为工具错误。服务错误按事件计数，不把同时发生的多条错误武断归并为独立故障，也不能单独据此归因于拓扑策略。

## 主实验准入

使用全部 6 份原始报告直接调用生产 `calibratedTokenLimit`，三个模型的 `allowed` 均为 `false`。只有 DeepSeek 禁重连单个样本满足校准条件；没有任何一对匹配臂同时合格，也没有生成安全阈值。闸门检查为离线调用，没有额外模型请求。

DeepSeek 自适应的 3 次未知总 token 来自成功收尾取消；Space Bunny 禁重连的 2 次和自适应的 4 次未知，各包含一次故障注入取消，其余来自成功收尾。LongCat 自适应的 6 次未知分别对应 3 次流空闲超时和 3 次期限收尾取消，且还存在未交付及输出截断。因此，成功答案本身不足以产生可信的“实测成本 × 2”阈值；校准要求成功、无截断且用量完整的一对匹配样本，所有匹配失败样本仍参与判断。

LongCat 禁重连的 5 次未知包含一次故障注入取消和四次期限收尾取消。后续闸门还应使用模型步骤截断计数，避免仅检查回合结束而漏记。本批次该差异不改变拒绝结论：对应运行同时存在超时、未知 usage 和回合截断。

本轮不补采成功样本、不扩大预算、不启动 2 任务 × 2 臂 × 3 重复的主实验。后续应先修复故障注入及收尾时的 usage 结算和聚合消息纪律，再重新登记校准；交付接管需要专门覆盖入口退休的场景。单任务、每配置一次的这些观察不能支持自适应拓扑收益的因果结论。
