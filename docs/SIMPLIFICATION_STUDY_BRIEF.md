# dsh-ATN 机制简化研究实施说明（修订版）

这份文档交给实现代理执行。**本轮不是收益研究，是移除决策研究。** 目标是回答：请求者评价机制与共享白板机制，在当前任务族上是否值得留在插件里。

**本修订版取代初版的第 3、4.2、4.3、4.4、5 节。** 初版存在一处严重的符号错误和一处样本量错误，见第 3 节。实现代理必须先读完第 3 节再动手。

## 0. 修订摘要

| 项 | 初版 | 修订后 |
|---|---|---|
| 非劣性判据 | `Δ_M` 区间**上界 < δ** | `Δ_M` 区间**下界 > −δ** |
| 样本量 | n ≥ 10 | 由 δ 决定；δ=25pp 需 **n ≥ 11**，且这是零不一致对的最佳情形 |
| 主指标 | 仅完成率 | 拆成"成本轴（可回答）"与"完成率轴（仅报告）" |
| 决策规则 | 统计非劣性检验 | 预先登记的判断：成本下降 **且** 损害区间满足边界 |

### 1.1 待检的点估计

| 臂 | 两阶段完成 | ATN 交互均值 | 完成运行模型调用均值 |
|---|---:|---:|---:|
| adaptive（全机制） | 3/5 | 42.33 | 82.00 |
| no-feedback（去掉评价） | 5/5 | 41.80 | 82.00 |
| no-board（去掉白板） | 3/5 | **26.00** | 73.33 |

去掉白板后交互量低约 40%，且该臂三次完成运行的交互数完全相同（区间 [26.00, 26.00]）——这是本轮最干净的信号。去掉评价后完成率最高，但 n=5 且五臂轮设计上不可能显著，只能作待检假设。

## 2. 本轮要回答的问题

对每个机制 M ∈ {请求者评价, 共享白板}：

> **去掉 M 是否降低协调成本？**（可回答）
> **去掉 M 是否造成实质完成率损失？**（昂贵，且很可能不结论）

以及当两者都可去掉时，同时去掉是否有补偿性交互。

产出是**每个机制的书面保留／移除建议及其依据**，不是自动删除。

## 3. 初版的两处错误（必读）

### 3.1 非劣性符号写反（严重）

初版定义 `Δ_M = 完成率(no-M) − 完成率(adaptive)`，并写"移除可被接受当且仅当 `Δ_M` 的 95% 区间**上界 < δ**"。**这是错的，而且错在危险的方向。**

移除造成损害时 `Δ_M < 0`。要排除"损害 ≥ δ"，必须排除 `Δ_M ≤ −δ`，即证明 `Δ_M > −δ`。区间为 `[L, U]` 时，这要求

```
L > −δ
```

初版规则的反例：若 `Δ_M = −0.10`、区间 `[−0.40, +0.20]`，初版规则看到上界 0.20 < 0.25 便"接受移除"，而区间下界 −0.40 说明**高达 40 个百分点的损害并未被排除**。初版规则会让研究**过度倾向于移除**，与本文件反复声明的"保守默认保留"完全相反。

**修订后的判据：移除可被接受，当且仅当 `Δ_M` 的 95% 区间下界 `L > −δ`。**

### 3.2 样本量不足

对配对二元结果，零不一致对时完成率差的 95% 上界用 Clopper–Pearson 为 `1 − 0.05^(1/n)`。实测：

| δ | 所需最小 n（零不一致对的最佳情形） |
|---:|---:|
| 40pp | 6 |
| 30pp | 9 |
| **25pp** | **11** |
| 20pp | 14 |
| 15pp | 19 |

n=10 时上界为 **25.89%**，大于 25pp，**即使十次结果完全一致也无法排除 25pp 损失**——与初版声称的 n≥10 矛盾。n=12 时上界为 22.09%，勉强通过。

**并且以上是零不一致对的最佳情形。** 实际运行中只要出现不一致对，区间就会变宽。因此在 n=12 下，完成率轴**很可能给出"不确定"**。

### 3.3 推论

完成率的非劣性判定在本项目的可行预算下**大概率得不到确定结论**。因此本轮把成本轴提为可回答的主指标（第 4.4 节），完成率轴降为"报告但不宣称"。

## 4. 设计

### 4.1 臂

| 臂 | 定义 |
|---|---|
| `adaptive` | 全部机制（对照） |
| `no-feedback` | 去掉请求者评价，保留其余 |
| `no-board` | 去掉白板，保留其余 |
| `minimal` | 同时去掉两者（检验补偿性交互） |

预算受限时优先减臂而非减 seed，并显式写明未检验项。

### 4.2 判据（修订后的符号）

- `Δ_M = 完成率(no-M) − 完成率(adaptive)`，区间 `[L, U]`。
- **移除可被接受 ⟺ `L > −δ`。**
- 报告必须同时给出 `minimal` 对 `adaptive` 的同一判据。
- 不得使用优效性检验支持移除；不得以点估计方向作为移除依据。
- 报告必须显式写出所用区间方法与不一致对数。

验收测试：

- 判据实现对 `Δ = −0.10, CI = [−0.40, +0.20], δ = 0.25` 的输入必须输出**不可接受**。
- 对 `Δ = 0.00, CI = [−0.20, +0.20], δ = 0.25` 必须输出**可接受**。
- 上述两条测试必须先于真实运行通过。

### 4.3 δ 与样本量（维护者预先登记）

**δ 是产品判断，不是统计参数**："为了移除这个机制，我愿意接受多大的完成率损失？"

流程：

1. 维护者先选定 δ，理由写进报告。
2. 用第 3.2 节的表推出最小 n，并**留出不一致对的余量**（建议在最小 n 上加 2–4）。
3. 功效分析落盘（含所选 n 下的最小可能 p 与可检出性判定），确认后再运行。
4. **不可在未确认可检出性的情况下开跑。**

建议起点：δ = 25pp、n = 12、四臂 = 48 次运行；或三臂 = 36 次。若接受更宽的 δ（例如 30pp），n 可降到 9–11。

seed 必须与既有轮次一致或可追溯同一生成规则，不得为得到更好结果挑选 seed。

### 4.4 主指标：拆成两轴

**轴 A —— 成本（可回答，主指标）**

- 每次运行的模型调用数、ATN 协议交互数、传输字节数、入口步数。
- 连续量，n=12 下功效良好；包含失败运行的消耗，失败与完成分别列出。
- 用于回答"移除是否降低成本"。已知基线：去掉白板后交互均值 26.00 对 42.33。

**轴 B —— 完成率（仅报告）**

- 两阶段完成率 + Wilson 区间；配对风险差 `Δ_M` + 区间。
- 只有在满足第 4.2 节时才可宣称非劣性；否则写**"不确定"**。
- 不得用轴 A 的成本下降替代轴 B 的判定。

未知 usage 一律保留为未知，不得记为零。费用是目录参考价估计，不得写成订阅账单。

### 4.5 每臂的参考对照（防配置错误）

真实运行前，对四个臂分别用构造性参考做零模型调用验证：四个臂都能换边，参考都应能完成。任一臂参考失败即为配置错误，不得把随后的模型失败归因于机制移除。

## 5. 决策规则（保守默认）

1. **默认保留。** 移除建议成立当且仅当：**轴 A 显示实质性成本下降，且轴 B 满足 `L > −δ`。**
2. **不确定即保留。** 区间过宽、不一致对不足、或 `minimal` 的交互判据不通过时，结论写"不确定"，不做移除建议。
3. **移除建议必须附带限制：** 结论只适用于当前任务族。若某机制有当前任务族激活不了的先验理由，必须显式列出该理由**未被检验**，最终决定交维护者，不得自动删除。
4. 不得因为"更便宜"而放宽轴 B。成本是附加依据，不是替代。
5. 全部 `causalClaim` 保持 false；本轮不提出任何收益主张。

## 6. 若不打算跑真实运行：现在就可以定的部分

本节给出**无需新增真实运行**即可成立的推理，供维护者在预算不足时使用。它不是统计结论，是依据现有证据的判断。

**共享白板 —— 建议保留。**
其先验理由是在事实多、广播频繁时避免唤醒同伴。本任务每节点约两条事实、邮件足够，该理由**从未被激活**，因此"去掉不影响完成率"不能外推。而它的移除收益（交互 −40%）只在成本上成立。用一个未激活场景的任务族去删一个为此设计的机制，风险大于收益。

**请求者评价 —— 待定，可倾向移除。**
该机制在本任务中**确实被激活**：五臂比较记录到 18 次 rejected，说明请求者真的做了判定。在这种"机制被激活"的条件下仍未观察到完成率收益，是比白板更强的移除依据。但 n=5 不足以定论，且该机制已并入 `atn_status`，边际工具面成本已很小。

维护者若选择不跑，建议结论写为：白板保留并注明理由未检验；评价保留但标注"在本任务族上未观察到收益，是后续简化的首要候选"。

## 7. 必须保留的既有语义

- 入口 Agent 由宿主拥有；完成、停止、退休都不 `dispose` 入口。
- 网络记录是唯一原子持久化单元；"检查 + 修改"在同一 mutation 临界区内完成。
- 边是单向的；出生谱系只作追溯。
- 工具身份、发送者、投票者取自真实 live Agent。
- 同伴文本不构成人类授权；请求者评价不构成宿主验收。
- 同能力原则：限制的是信息可达性，不是能力。
- `stepBudget` 不得被宣称成 token、HTTP 请求或费用上限。
- 正向事实流审计继续对全部真实运行执行。
- 任务、ACL、fixture、预算、模型在本轮**全部冻结**；只改变臂的机制组成。

## 8. 不要做的事

1. 不新增模型工具，不新增机制。
2. 不在功效分析确认可检出性之前开始真实运行。
3. 不使用初版的反向符号判据。
4. 不用优效性检验支持移除。
5. 不缩小 seed 数来省预算；优先减臂。
6. 不挑选 seed、不删除失败样本、不补跑成功样本。
7. 不改任务、ACL、fixture、预算或模型。
8. 不自动删除机制；只出建议。
9. 不删除已有测试，不降低断言强度。

6. 报告显式写出本轮**未**主张收益，全部 `causalClaim=false`。
7. README 与本轮报告同步记录实际通过项与未完成项。**不得把未测试内容写成已通过。**
