## 2. 本轮已确证的事实

### 2.1 固定失败是结构性的，不是模型能力问题

零模型调用的构造性参考在 adaptive 上 5/5、fixed 上 0/5，两者使用同一 ACL、fixture 与预算。参考是一个能干的执行者，它在 fixed 上同样无法取得任何必需事实。**"fixed 失败是因为模型太弱"这个替代解释已被排除。**

### 2.2 现有自适应臂的能力水平约为 67%

最近三次独立批次的同模型 adaptive 探针为 **3/5、4/5、3/5**（合并约 10/15）。各批次源码略有不同，不能直接合并做正式估计，但足以判断量级。

### 2.3 能力闸门统计上不成立

上一轮 4.3(3) 要求探针 ≥4/5。若真实完成率 p≈0.7，则

```
P(X ≥ 4 | X ~ Binomial(5, 0.7)) = C(5,4)·0.7⁴·0.3 + 0.7⁵ ≈ 0.53
```

**一个能力达标的模型只有约一半概率通过该闸门。** n=5 时 3/5 与 4/5 的 Wilson 95% 区间分别约为 [0.19, 0.81] 与 [0.28, 0.99]，大幅重叠，不构成可区分的判定。

该闸门测的是抽样运气，不是能力，且已连续阻断两轮工作。这是连续第四轮出现闸门错误，错法为**在小样本上设点估计阈值且未做功效分析**。

**本轮起：小样本点估计不得用作通过／不通过闸门；能力只能以区间形式报告。**

### 2.4 缺少隔离"自适应 vs 边数"的对照臂

当前比较是 adaptive（出度 2、可换边）对 fixed（出度 2、不可换边）。两者同时相差"能否换边"与"边数是否够用"。需要补一个**出度 4 的静态臂**，才能把"自适应"与"边够多"分开。

初步分析（须由本轮实测确认）：即使出度 4，静态臂仍无法覆盖两个阶段——第二阶段更换持有者，而白板只允许当前阶段的 `phase-N:` 键，因此静态臂在第一阶段无法预知第二阶段的持有者，只能盲猜。这提示绑定是稳健的，但必须作为对照臂实测出来。

## 3. 目标

- **G1 替换闸门**：删除小样本点估计闸门，改为区间报告与显式功效声明。
- **G2 补齐对照臂**：新增静态出度 4 臂，隔离"自适应"与"边数"。
- **G3 主指标改为连续量**：以小样本可检出的效率指标为主，二元成功率以区间报告。
- **G4 执行比较**：完成全部臂的运行并如实报告。

## 4. 必须实施的项目

### 4.1 删除小样本点估计闸门

要求：

- 删除"探针 ≥4/5"这类通过／不通过闸门。
- 替换为：比较**直接执行**，只要自适应臂在比较中至少有 1 次完成两阶段；若为 0，则报告"无可比信号"并停止解释。
- 所有完成率必须以 **Wilson 区间**报告，并给出该样本量下的**最小可检出效应**。
- 报告中必须显式写出：在 n=5 下，约 60 个百分点以下的效果不可靠区分。

验收测试：

- 汇总器对 n=5、3/5 与 4/5 的输入输出区间而非通过／不通过判定。
- 功效说明随每个完成率一并输出。

### 4.2 新增静态出度 4 对照臂

要求：

- 新增臂 `fixed-wide`：`maxCollaborationPeers=4`，禁止主动换边，其余机制与 `adaptive` 相同。
- 该臂的初始边集合必须**只依据运行时公开可得的信息**选取（不得读取隐藏 fixture、不得预知第二阶段持有者）。具体选边策略须在报告中写明并固定。
- 该臂用于回答：**自适应的优势是否只是"边够多"**。
- 判定规则：
  - 若 `fixed-wide` 完成率与 `adaptive` 相当 → 优势来自边数，不是自适应；
  - 若 `fixed-wide` 明显低于 `adaptive` → 自适应有独立作用；
  - 两者都必须在报告中以区间形式给出。

验收测试（确定性、零模型调用）：

- 用构造性参考在 `fixed-wide` 拓扑上运行全部 5 个 seed，落盘取得的必需事实数与入口步数。
- 断言该臂的选边策略不读取任何第二阶段信息（静态检查其输入来源）。

### 4.3 主指标改为连续量

要求：

- 主指标从"两阶段正确"改为**每次完成运行的模型调用数**（次要：ATN 协议交互数、传输字节数、入口步数）。
- 参考基线：同拓扑构造性参考为 **0 次模型调用、27 入口步、19 消息**（adaptive）。
- 连续指标必须报告均值与区间，并说明未知 usage 的处理（未知不得记为零）。
- 二元完成率继续报告，但降为次要指标并以区间呈现。
- 只有完成两阶段的运行才计入效率统计；失败运行的消耗单独列出，不得混入。

验收测试：

- 汇总器对"完成 3 次、失败 2 次"的输入分别给出效率统计与失败消耗，不合并。

### 4.4 执行比较

要求：

- 臂：`adaptive`、`fixed`、`fixed-wide`、`no-feedback`、`no-board`。各臂 ≥5 次，配对 seed 相同。
- 同一模型、预算、fixture、源码；预算变更须为显式条件且各臂一致。
- 只使用在探针中表现可用的模型；LongCat 明确排除。
- 失败、超时、工具异常、未知 usage 全部保留。
- 报告必须给出每臂的：完成率及区间、效率指标及区间、`accepted`／`rejected`、换边尝试／成功／拦截、最大节点步数占比。
- **必须明确写出哪些臂之间的差异在本样本量下不可区分。**

### 4.5 收益主张的边界（不可放宽）

要求：

- `fixed` 与 `fixed-wide` 的失败若是结构性的，必须表述为**任务设计的后果**，不得写成自适应收益。
- 收益主张只有在 `adaptive` 相对 `no-feedback`、`no-board` 与 `fixed-wide` 都表现出一致且超出区间的优势时才可提出。
- 否则只能陈述为："在拓扑绑定的任务上，可换边臂能够完成，其余臂结果见报告；本样本量不足以区分 X 与 Y。"
- 全部 `causalClaim` 保持 false。

## 5. 必须保留的既有语义

- 入口 Agent 由宿主拥有；完成、停止、退休都不 `dispose` 入口。
- 网络记录是唯一原子持久化单元；"检查 + 修改"在同一 mutation 临界区内完成。
- 边是单向的；出生谱系只作追溯。
- 工具身份、发送者、投票者取自真实 live Agent。
- 同伴文本不构成人类授权；请求者评价不构成宿主验收。
- 白板作者权限、精确版本、分页失效与读写计量语义不变。
- 同能力原则：限制的是信息可达性，不是能力。
- `stepBudget` 不得被宣称成 token、HTTP 请求或费用上限。
- 正向事实流审计继续对全部真实运行执行。

## 6. 不要做的事

1. 不新增模型工具。
2. 不以小样本点估计作为通过／不通过闸门。
3. 不以违规次数、拦截次数作为强制生效判据。
4. 不通过提高预算或增加重复来让某个闸门"通过"；重复数是预先确定的设计量，不是事后补足的手段。
5. 不改生产默认值。
6. 不删除已有测试，不降低断言强度。
7. 不把结构性失败写成自适应收益。
8. 不删除失败样本或补跑成功样本。
