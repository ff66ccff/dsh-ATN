# ATN 可丢弃验证原型

**THROWAWAY — 不是正式插件，不连接真实模型。** 用确定性模型替身驱动真实 DeepSeek Harness `0.2.0-rc.2` Agent、工具执行和 JSONL Session，检验 [设计讨论稿](../docs/atn-source-analysis-and-design.md) 中的拓扑、全票审议和正常退休机制。

验证问题：一个节点退出新工作拓扑后，能否继续完成旧任务和旧审议，而新提案使用自动补位后的邻居，独立后代继续工作？

## 运行

需要 Node.js 24+。以下命令在本仓库根目录执行。

首次安装（依赖版本由 lockfile 锁定，不运行安装脚本）：

```bash
npm --prefix prototype ci --ignore-scripts
```

一条命令自动执行全部检查点：

```bash
npm --prefix prototype run verify
```

逐步终端演练：每步执行前按 Enter，输入 `q` 结束；非交互终端自动执行：

```bash
npm --prefix prototype run explore
```

类型检查：

```bash
npm --prefix prototype run typecheck
```

每步打印相关完整状态：节点阶段、出生者、所选路径、当前邻居、未完成任务和审议、提案选民与投票、当前目标版本、信箱和请求计数。

## 实际用了什么

- 真正的 Cordis 插件作用域、Harness Agent factory / loop、工具注册与执行、Session 日志和 JSONL 持久化。
- 同一模型替身、同一工具集供所有节点使用；脚本通过真实模型工具调用触发 ATN 行为，而非只调用状态转换函数。
- 每个节点由网络插件作用域创建，不指定运行时 `parentAgent`；出生来源单独持久记录。
- 目标文档快照通过 `agent/pre-step` 进入可回放的节点输入，实际读取版本和正文保留在 Session 中。
- 网络状态使用独立的原子替换 JSON 临时快照。它只验证协议，不是正式 `storageDomain` 实现。

这是参考上游内核 fixtures 的**进程内验证装配**，不是另一个产品启动器，也没有声称验证了 `dsh` profile/bundle 安装路径。

## 演练范围

19 个检查点覆盖：

1. 空闲不等于任务完成；无邻居不能自行批准文档变更。
2. 连续多代创建，每个节点都能继续派生；中心节点四个邻居推导。
3. 多分支存在但不自动替换首个选中子节点；同构工具集。
4. 按需发现非邻居、跨分支通信；运行时提供真实发送者身份。
5. 固定审议名单，以及并发的旧版本提案。
6. 中间节点进入 `draining`，向外补位但不丢旧审议；拒绝新任务。
7. 新提案使用新邻居；旧邻居无权投新提案；一票反对不通过。
8. 三票赞成不能代替四票全体赞成。
9. 退出中的节点接收已有工作的结果、投旧票、完成自身任务后释放；后代继续存活。
10. 即使全票同意，旧基础版本也不能覆盖更新后的目标。
11. 完成任务后保留节点并接收新任务；新目标正文和版本被记录。
12. 部分投票持久化；模拟目标已保存消息而发送方丢失回执。
13. 整个运行时退出后重新启动，从真实 Session 日志恢复；消息不重复进入上下文，预算不重置。
14. 恢复后的投票完成一次提交；重复投票不重复生成目标版本。
15. 全部任务结算、交付给 USER，关闭所有真实 Agent handle。
16. 任务驱动续期、逻辑时钟到期、并发及累计创建上限。
17. 沉默不算赞成；提案超时后迟到投票不能使其生效。
18. 硬停止后不能投票、续期或创建，资源得到清理。
19. 跨节点模型请求额度受限，不因空闲而重置。

## 产物与文件

每次自动演练创建全新的 `.scratch/PROTOTYPE-WIPE-ME-*` 目录，不接触真实工作区或用户的 Harness 数据。恢复场景会在同一临时目录中销毁和重建整个内核。

- `evidence/latest.json`：最新运行结果、检查点状态、脚本化请求摘要和真实 Session 事件。重复运行会覆盖它。
- `.scratch/PROTOTYPE-WIPE-ME-*/`：标记为可丢弃的网络快照和 Session 日志，便于复查；不自动删除。
- [验证报告](../docs/atn-prototype-validation.md)：本轮结果和适用范围。
- `harness.ts`：真实内核装配与模型替身。
- `state.ts`：拓扑、任务、文档投票和临时持久化。
- `runtime.ts`：网络资源所有权、同构工具、投递、输入记录与释放。
- `cli.ts`：自动／交互式演练及检查点。

## 明确没有验证的部分

- 真实 LLM 的自治决策、任务质量、成本优势或群体智慧。
- 正式 plugin bundle/profile、Web UI、HMR 全场景、沙箱和审批权限继承。
- 进程强杀、断电、多进程并发、真实磁盘故障或外部副作用恰好执行一次。
- 创建尚未发布时的崩溃恢复（原型恢复到 `provisioning` 会明确失败）。
- 生产级调度、长期运行与吞吐：租约采用可推进的逻辑时钟，演练驱动器在步骤间收敛工作和释放资源；网络快照为同步整份写入。
- 任意修改主分支的管理操作；当前仅验证首个子节点选择及沿原路径自动绕过退出节点。

到路径尽头先留空，不自动跳到别的子分支。这遵循讨论稿的暂定边界处理；若需要跨分支自动补位，应先明确规则。

没有真实模型网络 adapter，也没有 shell、文件编辑等工作区操作工具。通过本原型**不能推出**正式部署的权限继承已经正确。
